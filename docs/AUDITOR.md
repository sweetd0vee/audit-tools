# Как аудитор банка работает с агентом

Агент **v0.0.1**. Полный гайд (навигация Open WebUI, пользовательские истории, что видит LLM): [`GUIDE.md`](GUIDE.md). Ниже — краткая шпаргалка фаз и команд. Как устроено саммари на большой библиотеке: [`SAMMARI.md`](SAMMARI.md). Что добавляем после демо: [`PLAN.md`](PLAN.md).

Один вход: [http://localhost:3000](http://localhost:3000).  
Модель в новом чате: **Аудитор** (не `qwen3.8:27b` и не другие модели с иконкой `ol` — это обычный чат без рук).

Агент ведёт **одну проверку в одном чате**. Не смешивайте две темы в одном окне. Новая проверка — новый чат.

Инвариант:

> Модель ускоряет поиск нормы и черновик обзора. Она не ставит аудиторское суждение и не заменяет чтение первоисточника. Цитата проверяется по файлу в кейсе.

Клиентские данные и формулировки проверки **не уходят в интернет**. Поиск актов — только по официальным доменам РБ.

---

## 1. Пользовательская история целиком

Вы — внутренний аудитор банка в Республике Беларусь. На этой неделе проверка **аренды коммерческой недвижимости**: валютные расчёты, НДС, договоры с нерезидентами.

Раньше вы делали это руками: вспоминали акты, искали редакции на pravo.by, читали десятки страниц, выписывали 5–7 норм в рабочую бумагу.

Теперь:

1. Открываете чат **Аудитор** и одной фразой описываете проверку.
2. Агент предлагает список НПА. Вы **утверждаете** номера — без этого ничего не качается.
3. Система скачивает официальные тексты в папку кейса, режет на статьи, собирает индекс.
4. Вы пишете `саммари` и читаете Word со ссылками на статьи, а не весь ГК.
5. Спрашиваете норму так: `вопрос …`. Ответ приходит с цитатой из *этой* библиотеки. Без префикса — обычный чат, не цитата. Нет фрагмента — агент так и говорит.
6. По желанию: `саммари total` (конспект из знаний модели) и `программа проверки`.
7. Главный продукт планирования: `гипотезы` → Excel-чеклист 8–10 гипотез для проверки (опирается на саммари / total / программу / НПА).
8. Подтверждаете часть гипотез (`утверждаю гипотезы 1, 3, 5`; свои можно приложить .xlsx) → `аудиторское мнение` — черновик раздела I; затем `аудиторское заключение` — полный черновик в Word.

Данных клиента, тестов и working papers в **v0.0.1 нет** — это [план v0.4–v0.5](PLAN.md). Демо закрывает кусок «собрать норму → сформулировать гипотезы → черновик мнения и заключения».

```
Описать проверку
  → список актов (модель предлагает)
  → вы утверждаете номера          ← стоп-кран
  → скачивание с pravo.by / nbrb.by
  → индекс + (по команде) Word-саммари / программа / total
  → `гипотезы` → Excel-чеклист
  → `утверждаю гипотезы 1, 3, 5`  (+ свой .xlsx по желанию)
  → `аудиторское мнение` → Word раздела I
  → `аудиторское заключение` → Word полного черновика
  → `вопрос …` по норме с цитатами
  → без префикса — обычный чат
```

## 2. Первый сеанс: что нажимать

1. Compose уже поднят: `docker compose up -d --build`.
2. Откройте http://localhost:3000, войдите.
3. **Новый чат**. В выборе модели найдите **Аудитор** (в поиске наберите это слово).
4. Если агента нет в списке — его ещё не вставили в Admin → Функции. Это делает админ по [`seed/openwebui/AGENT.md`](../seed/openwebui/AGENT.md).

Писать можно сразу. Команды `помощь` / `help` / `?` показывают краткую шпаргалку в чате.

## 3. Что писать на каждом шаге

### Шаг 1. Описать проверку

Одна строка. Лучший шаблон:

```
Проверка <тема>, <ключевое слово 1>, <слово 2>, <слово 3>
```

Примеры, которые агент поймёт как новый кейс:

```
Проверка аренды коммерческой недвижимости, аренда, валюта, НДС
```

```
Аудит кассовых операций, касса, лимит остатка, подотчёт
```

```
Проверка валютного контроля по экспортным контрактам, валютная выручка, срок репатриации
```

Как парсится:

| Кусок сообщения | Что станет |
|---|---|
| Текст до первой запятой | Название проверки |
| Остальные куски через запятую | Keywords для поиска и саммари |

Не надо JSON, не надо «создай кейс». Не начинайте с `вопрос …` — агент не создаст проверку. Обычный «какой срок…» без кейса уйдёт в свободный чат.

Плохо:

```
аренда
```
(слишком коротко / не похоже на проверку)

```
вопрос Какой срок возврата валютной выручки?
```
(это вопрос к базе — и кейса в чате ещё нет)

Хорошо: сначала проверка, потом вопросы.

**Под капотом.** Pipe видит, что текст похож на проверку (`проверк` / `аудит` / `аренда` / …). Вызывает `POST /api/v1/cases`, затем `POST …/propose`. Модель выбирает акты **из каталога** `known_sources` (у каждого уже есть официальный URL); код отбрасывает названия вне каталога. В ответ чата вшивается скрытая метка `<!--audit-case:abc123-->` — так следующие сообщения остаются в том же кейсе. **Файлы ещё не качаются.**

Ждите 1–3 минуты. Статус: «Подбираю список документов (npa). Это может занять несколько минут…».

---

### Шаг 2. Прочитать список и ответить

Агент пришлёт нумерованный список, например:

```
1. Гражданский кодекс Республики Беларусь — обязательно
2. Налоговый кодекс … — обязательно
3. Инструкция НБРБ … — желательно
…
```

Приоритеты:

- **обязательно** (`priority=1`) — без этого проверку по теме не начать;
- **желательно** (`2`);
- **опционально** (`3`).

Вы — человек в контуре. Список можно урезать, расширить ссылкой, не утверждать «всё подряд». Модель могла предложить лишний акт или устаревшее название.

#### Утвердить часть списка

```
утверждаю 1, 2, 4
```

Синонимы, которые тоже сработают: `подтверждаю`, `выбираю`, `скачивай`, `скачай`, `бери эти акты`.

#### Только обязательные

```
утверждаю все обязательные
```

Это **не** «все из списка», а только пункты с пометкой «обязательно».

#### Добавить акт, которого нет в списке

Если модель не предложила нужный документ, допишите **название** — сервер сам попробует найти официальный текст и положить в базу знаний.

```
утверждаю 1, 2, 4 плюс Инструкция НБРБ № 38; Положение о внутреннем контроле
```

Несколько названий разделяйте точкой с запятой, переносом строки или ` + `. Можно и так:

```
утверждаю все обязательные
плюс Закон о валютном регулировании и валютном контроле
```

Если список уже утверждён, достаточно:

```
добавь Инструкция о порядке проведения валютных операций
```

Название пишите как можно ближе к официальному (тип акта + номер или точная цитата из заголовка). Если поиск не найдёт URL — пришлите ссылку: `к N url https://pravo.by/document/?guid=…`.

#### Приложить официальную ссылку

Если вы уже открыли акт в браузере — вставьте **полный** URL, как в адресной строке. Многоточие `...` агент отвергнет.

```
к 3 url https://pravo.by/document/?guid=3871&p0=Hk9900218
```

Можно вместе с утверждением:

```
утверждаю 1, 2, 3, к 3 url https://pravo.by/document/?guid=3871&p0=Hk9900218
```

Домены только из allowlist: `pravo.by`, `pravo.gov.by`, `etalonline.by`, `nbrb.by`, `minfin.gov.by`, `nalog.gov.by`, `government.by`, `president.gov.by`.

#### Не утверждать

Просто напишите, чего не хватает или что лишнее, **без** слов «утверждаю / скачай». Агент не качает. Если список совсем не тот — новый чат и более точные keywords.

**Под капотом.** Pipe разбирает номера (`1` = первый в списке) и блок после `плюс` / `добавь` (названия актов). `POST …/select` помечает выбранные id и **добавляет** `extra_titles` в список кейса. Сразу за этим `POST …/download`: для каждого акта URL берётся в порядке

1. ваша ручная ссылка,
2. curated `known_sources` (известные официальные URL по названию),
3. SearXNG строго по allowlist (для актов «от себя» — запросы из названия).

Уже скачанный файл повторно не трогается. HTML/PDF кладётся в `knowledge_raw/`, из него извлекается текст в `knowledge_text/`, текст режется на чанки (в т.ч. по статьям), пишется `knowledge_index.json`. Если в Valves агента задан ключ Open WebUI — очищенный `.txt` заливается в коллекцию Knowledge этого кейса.

### Шаг 3. Если что-то не скачалось

Агент напишет «скачано N, ошибок M» и список провалов.

Повторить с запасным официальным URL (уже скачанное не перезапишет):

```
скачай
```

или

```
скачай ещё раз
```

Подложить недостающую ссылку:

```
к 5 url https://nbrb.by/...полный-путь...
```

Посмотреть, что лежит в кейсе:

```
документы
```

Синонимы: `библиотека`, `файлы`, `архив`, `покажи акты`.

В ответе будут ссылки в браузер:

- zip скачанных актов (`…_npa.zip`);
- Word-обзор — после команды `саммари` (`…_summary.docx`).

**Под капотом.** `документы` → `GET /api/v1/cases/{id}/library`. Повтор `скачай` без новых номеров берёт уже утверждённые id и снова гоняет download.

### Шаг 4. Попросить саммари

Когда библиотека скачана и вы готовы читать глазами, а не кодекс целиком:

```
саммари
```

Синонимы: `сводка`, `бриф`, `docx`, `word`, `обзор актов`, `файл word`.

Чего ждать: несколько минут (модель пишет карточку на каждый акт, потом обзор проверки). В чат **полный текст не выкладывается** — придёт ссылка на Word и короткий дайджест.

Откройте:

```
http://localhost:8100/api/v1/cases/{case_id}/knowledge/summary.docx
```

В файле:

- обзор нормативного контура проверки;
- карточка по каждому скачанному акту (зачем нужен, ключевые нормы, что смотреть, пробелы);
- приложение: фрагменты `[n]` со статьёй/пунктом и официальным URL.

Номера `[n]` в тексте — это не статьи закона, а ссылки на фрагменты в конце файла. Статья указана рядом с фрагментом.

Пересобрать после того, как докачали ещё акты:

```
саммари заново
```

Повтор без `заново` отдаст уже готовый файл, если библиотека не менялась.

**Под капотом.** `GET …/knowledge/brief/stream`. Для каждого акта: короткий — one-shot; длинный — query-focused RAG (BM25+эмбеддинги → RRF → MMR → один stuff-вызов), не map-reduce по всему кодексу. Затем синтез обзора. Word в `summaries/`. Масштаб: [`SAMMARI.md`](SAMMARI.md).

---

### Шаг 4а. Попросить программу проверки

Когда есть кейс (лучше — уже скачанная библиотека), напишите:

```
программа проверки
```

Синонимы: `программу проверки`, `составь программу`, `программа аудиторской проверки`.

Чего ждать: несколько минут, один длинный вызов модели. В чат полный текст не выкладывается — придёт ссылка на Word.

Откройте:

```
http://localhost:8100/api/v1/cases/{case_id}/knowledge/program.docx
```

В файле: цель и задачи, границы, нормативные критерии по праву РБ, риски, аудиторские процедуры (что запросить у банка, как проверить, критерий с `[n]`), выборка, рабочие документы. Это черновик СВА, не утверждённая программа и не суждение.

Пересобрать:

```
программа проверки заново
```

**Под капотом.** `GET …/knowledge/program/stream`. Название проверки + keywords + приложенные акты/фрагменты → локальная LLM пишет программу. Word в `programs/`.

### Шаг 4б. Попросить саммари total

Конспект по теме **из знаний модели**, не из скачанных файлов:

```
саммари total
```

Синонимы: `конспект модели`. Голое `total` / `тотал` не срабатывает. Пересборка: `саммари total заново`.

Это не цитата из кейса. Сверяйте номера с первоисточником или с `саммари`. Word: `…/knowledge/total.docx`, папка `totals/`.

---

### Шаг 4в. Гипотезы и мнение

Когда есть кейс (лучше — саммари / программа), напишите:

```
гипотезы
```

Откройте Excel, отметьте, какие гипотезы подтвердились на проверке:

```
утверждаю гипотезы 1, 3, 5
```

или `утверждаю гипотезы все с приоритетом высокий`, или `утверждаю все гипотезы`.

Свои гипотезы, которых нет в чеклисте, — допишите строки в тот же Excel (колонка «Гипотеза») или сделайте отдельный .xlsx и **приложите файл** к сообщению:

```
утверждаю гипотезы 1, 2, 3, 4
```

(файл прикрепляете в чат вместе с фразой). Если номера уже подтверждены:

```
добавить гипотезы
```

и снова приложите .xlsx. Эти строки тоже войдут в мнение и в наблюдения заключения.

Затем черновик раздела I аудиторского заключения (2–4 страницы, повествование, без таблиц):

```
аудиторское мнение
```

Шрифт: `-c` Calibri, `-t` Times New Roman (по умолчанию Times New Roman):

```
аудиторское мнение -c
```

Пересборка: `аудиторское мнение заново`. Файл: `…/knowledge/opinion.docx`, папка `opinions/`. В чат полный текст не копируется. Это черновик для руководства банка, не подписанный акт СВА. В текст идут только подтверждённые гипотезы.

**Под капотом.** `POST …/hypotheses/select`, затем `GET …/knowledge/opinion/stream`.

После мнения — полный черновик заключения (титул, содержание, раздел I как есть, наблюдения по шаблону, общая информация). Раздел II не пишется:

```
аудиторское заключение
```

Шрифт тот же: `-c` / `-t`. Пересборка: `аудиторское заключение заново`. Файл: `…/knowledge/conclusion.docx`, папка `reports/`. Нужны и подтверждённые гипотезы, и уже собранное мнение.

**Под капотом.** `GET …/knowledge/conclusion/stream?font=c|t`.

### Шаг 5. Спрашивать норму

Вопросы к базе пишите в **том же чате**, где создали кейс. Сообщение **начинайте со слова `вопрос`**:

```
вопрос Какой срок возврата валютной выручки по аренде нерезиденту?
```

```
вопрос Можно ли устанавливать арендную плату в валюте для резидентов РБ?
```

```
вопрос Какая статья НК регулирует НДС при сдаче в аренду нежилого помещения?
```

Без префикса `вопрос` это обычный диалог: модель ответит из своих знаний, блока цитат не будет — не тащите такой ответ в рабочую бумагу как норму.

Как спрашивать, чтобы цитата нашлась:

- префикс `вопрос` обязателен;
- называйте предмет («аренда нежилого», «валютная оговорка»), а не «расскажи про аренду»;
- если знаете акт — скажите его («в инструкции 38», «по НК»);
- один вопрос за сообщение.

Плохо: `Можно ли …?` без слова `вопрос`.  
Плохо: `вопрос Расскажи всё про аренду`.  
Плохо: `вопрос Сколько начислено аренды по договору №17?` (факт клиента, контура ещё нет).

Ответ: текст + блок **Откуда** с обрезками фрагментов. Если фрагментов нет — не считайте ответ нормой.

**Под капотом.** `POST …/knowledge/ask`. Вопрос эмбеддится той же моделью, что индекс (`qwen3-embedding:latest`). Чанки ранжируются: пересечение слов + cosine. Top-k фрагментов кладутся в промпт. LLM отвечает **по этим кускам**. Веб-поиск выключен.

| `программа проверки` | Сборка Word-программы проверки |
| `программа проверки заново` | Принудительная пересборка программы |
| `гипотезы` | Excel-чеклист 8–10 гипотез для проверки |

| `аудиторское заключение` / `-c` / `-t` | Черновик полного заключения в Word |
| `вопрос …` | Ответ по базе знаний с цитатами |

## 4. Диалог целиком (эталон)

Ниже — реалистичный сеанс. Ваши реплики можно копировать как шаблон.

**Аудитор**

```
Проверка аренды коммерческой недвижимости, аренда, валюта, НДС
```

**Агент** (через минуту) — кейс `a1b2c3d4`, нумерованный список 10–15 актов, просьба утвердить. Ничего не скачано.

**Аудитор** (глядя на список: ГК и НК берёте, инструкцию НБРБ тоже, методичку с приоритетом 3 пропускаете; на пункт 4 уже есть вкладка pravo.by)

```
утверждаю 1, 2, 4, 5 плюс Инструкция НБРБ № 38, к 4 url https://pravo.by/document/?guid=3871&p0=Hk9900218
```

**Агент** — «скачано 4, ошибок 1», ссылки на библиотеку, что можно спросить норму или написать `саммари`. Если один акт упал — список ошибки.

**Аудитор**

```
к 7 url https://nbrb.by/legislation/documents/...полный...
скачай
```

**Агент** — докачал. Уже лежащие файлы не тронул.

**Аудитор**

```
документы
```

Проверяете, что в zip лежат те акты, которые вы утвердили, а не «что модель вспомнила».

**Аудитор**

```
саммари
```

Качаете Word, читаете глазами. Помечаете места, которые пойдут в программу проверки.

**Аудитор**

```
вопрос Можно ли в договоре аренды с резидентом РБ устанавливать арендную плату в евро?
```

**Агент** — ответ + цитаты. Вы сверяете фрагмент с файлом в библиотеке, прежде чем тащить норму в рабочую бумагу.

**Аудитор**

```
вопрос Какой срок регистрации договора аренды нежилого помещения?
```

Если в библиотеке нет акта про регистрацию — отказ. Тогда либо утверждаете недостающий акт (новый select + `скачай`), либо ищете URL сами и даёте `к N url …`.

Новую проверку в этом чате не начинайте. **Новый чат → снова модель Аудитор.**

## 5. Что происходит под капотом (карта)

```
Вы (браузер :3000)
    │  обычные сообщения
    ▼
Pipe «Аудитор»          Python в Open WebUI Functions
    │  понимает фазу КОДОМ, не свободным ReAct
    │  HITL: download только после «утверждаю»
    ▼
Audit Tool Server       FastAPI :8100 — система записи кейса
    ├─ Ollama           qwen3.8:27b — propose, карточки, ответы
    ├─ Ollama embed     qwen3-embedding:latest — векторы чанков и вопроса
    ├─ SearXNG          поиск URL только по allowlist РБ
    └─ диск             backend/data/audit_cases/{case_id}/
```

Почему Pipe, а не «просто Qwen в чате»: локальная 27B плохо держит native tool-calling и может вызвать download без вашего «утверждаю». Фазу выбирает код. Модель предлагает список и пишет текст по фрагментам. Качать или нет — решаете вы.

### Папка кейса

```
backend/data/audit_cases/{case_id}/
  case.json               система записи: статус, кто выбран, URL
  manifest.json           что скачали, sha256, источник URL
  knowledge_raw/          первоисточники (html/pdf)
  knowledge_text/         очищенный текст
  summaries/              карточки актов + Word + brief.md
  totals/                 саммари total (из знаний модели)
  programs/               Word-программа проверки
  hypotheses/             Excel-чеклист гипотез
  opinions/               Word — раздел I (аудиторское мнение)
  reports/                Word — полное аудиторское заключение
  knowledge_index.json    чанки для вопросов
  library.zip             архив сырых файлов
```

### Как агент понимает ваше сообщение

Порядок проверок в Pipe (первое совпадение побеждает):

1. пусто / `помощь` / `?` → шпаргалка;
2. начинается с `вопрос` / `/ask` → ask по индексу;
3. `утверждаю гипотезы …` (+ свой .xlsx) → HITL: сохранить номера и гипотезы аудитора для мнения;
4. `аудиторское мнение` → Word раздела I; `аудиторское заключение` → полный черновик;
5. `программа проверки` → Word-программа;
6. `саммари total` / `конспект модели` → Word из знаний модели;
7. `гипотезы` / `чеклист гипотез` → Excel-чеклист;
8. `саммари` / `сводка` / `бриф` / `docx` → Word-обзор актов;
9. `утверждаю` / `скачай` / `плюс …` / `к 3 url …` → select + download;
10. `документы` / `библиотека` → список файлов;
11. `статус` / `кейсы` → состояние;
12. похоже на новую проверку **и в чате ещё нет кейса** → create + propose;
13. иначе → обычный чат (`POST /chat`).

Поэтому «Какой срок…?» без слова `вопрос` — не цитата. «Проверка аренды…» в чате с уже живым кейсом не создаст второй кейс. Новая проверка — новый чат.

Кейс привязан к **истории этого чата**. Если открыть новый чат — метки нет, библиотеки нет.

### Норма ≠ факт

| | Норма (v0.0.1) | Факт (план v0.4) |
|---|---|---|
| Что | НПА, инструкции НБРБ | Выгрузки, договоры, обороты |
| Откуда ответ | RAG по библиотеке кейса | SQL / tools по файлам клиента |
| Нельзя | Сочинять статью | Класть Excel в ту же Knowledge |

В чате с агентом не прикрепляйте клиентские Excel «чтобы модель посмотрела». Смешает закон и цифру.

### Чего агент не делает

- не ставит вывод «нарушение / не нарушение»;
- не подписывает working paper;
- не ищет по всему интернету;
- не качает акт, пока вы не утвердили номер или не дали URL;
- не считает ответ нормой, если блока цитат нет.

## 6. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| В списке моделей нет «Аудитор» | Админ: Functions, ID `auditor`, переключатель Включено, F5. См. [AGENT.md](../seed/openwebui/AGENT.md) |
| «Нет кейса в этом чате» | Опишите проверку заново в **этом** окне или не удаляйте историю агента |
| «Не поняла, какие акты утвердить» | `утверждаю 1, 2` — номера как в последнем списке |
| «Это не полная ссылка» | URL из адресной строки, без `...` |
| Акт не скачался | `скачай` или `к N url https://…` |
| «Audit Tool Server недоступен» | Compose: backend жив; Valves Pipe: в Docker `AUDIT_API=http://backend:8100` |
| Саммари долго / таймаут | Подождите или увеличьте `BRIEF_TIMEOUT_SEC` в Valves; повтор `саммари` |
| «Сначала подтвердите гипотезы» | `гипотезы`, затем `утверждаю гипотезы 1, 3, 5`, потом `аудиторское мнение` |
| Мнение долго / таймаут | Тот же `BRIEF_TIMEOUT_SEC`; повтор `аудиторское мнение` |
| Ответ без цитат / нет блока «Откуда» | Нет префикса `вопрос`, или акта нет в библиотеке. Напишите `вопрос …` |
| Модель выдумала РФ / IFRS | В библиотеке этого нет; не принимайте. Спросите с указанием акта РБ |
| Выбрали обычный Qwen, не Аудитор | Это чат без HITL и без кейса. Переключите модель |

Разработчикам: API без чата — [`backend/README.md`](../backend/README.md). Как устроен RAG — [`RAG_для_разработчика.md`](RAG_для_разработчика.md).
