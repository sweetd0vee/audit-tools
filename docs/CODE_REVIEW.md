# Code review: Audit Tools

**Дата:** 27 августа 2026  
**Объект:** `audit-tools`, `main`, демо v0.0.1  
**Объём:** ~12–14 тыс. строк своего Python (backend + Pipe + тесты), без форка Open WebUI  
**Модель использования:** один администратор за клавиатурой, аудитор рядом. Учётки, роли и число пользователей — не скоуп. Цель — выделенный хост в контуре банка, не портал отдела.

**Вердикт:** сильный доменный прототип. Для сеанса СВА (оператор + аудитор) — готов. Для постоянного хоста в контуре — почти: не хватает секрета на API и пинов образов. IAM и «второй пользователь» не блокер.

Шкала 1–10 — код и инженерная гигиена, не качество юридической выдачи модели.

| Измерение | Балл | Комментарий |
|---|---|---|
| Продуктовая архитектура | **8** | Сборка, не форк. HITL, норма ≠ факт, allowlist — в коде. Пара оператор/аудитор совпадает с фазами в Pipe |

## Модель использования (рамка ревью)

За системой сидит администратор. Аудитор читает список актов, Word/Excel и цитаты, говорит «утверждаю 1, 2, 4». Суждение и HITL остаются у аудитора; клавиатура — у оператора.

Из этого следует:

| Тема | В скоупе? | Заметка |
|---|---|---|
| Выделенный хост в периметре, loopback, локальная Ollama | да | Уже заложено в compose |
| Shared secret на API | да | ИБ, не «логины аудиторов» |
| Пины digest образов | да | Воспроизводимый контур |
| Роли, LDAP, N пользователей, «четыре глаза» в UI | нет | Не проектировать |
| Засев Pipe при `compose up` | удобство оператора | Тот же админ вставит функцию руками; не P0 контура |
| SQLite / «открой кейс X» | нет, пока один оператор | Не из-за второго пользователя |

Угроза CR-02 — не «аудитор из соседнего кабинета открыл UI». Это любой процесс **на хосте оператора** (браузер, плагин, малварь) бьёт в `:8100` без секрета. Open WebUI свой логин backend не закрывает.

---

## Что сделано правильно

1. **Граница кода.** FastAPI — система записи. Open WebUI — витрина. Pipe вызывает API, не дублирует download/RAG.
2. **HITL в коде.** Скачивание только после `/select`. Мнение только после `утверждаю гипотезы`. На сеансе это голос аудитора, не кнопка самообслуживания.
3. **Allowlist на hop редиректа** + curated `known_sources`. Поиск по умолчанию SearXNG; DDG/Bing за `NPA_WEB_FALLBACK`.
4. **RAG не top-k cosine:** multi-query, BM25 + dense, RRF, rerank, MMR. Пустая evidence → отказ, не преамбула кодекса.
5. **Промпты снаружи** (`docs/prompts`, ~31 файл). Артефакты через `run_llm_artifact_events`.
6. **Тесты на боли продукта**, не `assert True`. CI живой.

## Что ещё открыто

### P0 — без этого ИБ не подпишет хост в контуре

**CR-02. API без аутентификации.** CORS и loopback уже сузили периметр. Этого мало для политики банка: с той же машины, где сидит оператор, любой локальный процесс ходит на `:8100`. Нужен shared secret из env (Pipe и ручные вызовы). Не строить пользователей и роли.

### P1 — будет стоить недель (не блокер первого сеанса в контуре)

| ID | Суть |
|---|---|
| CR-09 | Нет полного TestClient create → select с mock propose. Live eval не гейт CI |
| CR-10 | Нет экспорта метрик времени; request id не в Ollama payload |

Pipe по-прежнему NLP на regex — это не P1. Новый тип проверки не требует трогать парсер фраз; синонимы команд — да. Не ждать LangGraph. Команды учит один человек.

## Архитектура vs `ARCHITECTURE.md`

Совпадает: нет SPA, кейс на диске, Pipe = фазы, `вопрос` → `/ask`, промпты снаружи. Один вход под оператора — так и задумано.

Расхождение, которое ещё важно: без ключа Pipe при `up` не появится (оператор вставит руками); trail полный (file/chunk/url) есть только у download-manifest и `trail/ask.jsonl`.

## Дальше, по порядку

Не делать микросервисы, React, Postgres «на вырост», роли, LDAP, мультипользовательский workflow.

1. Auth на API (секрет из env) — единственный P0 контура.
2. Пинить digest образов (`searxng:latest`, `open-webui:main`).
3. TestClient create → select без Ollama.
4. Засев Pipe при `up` — когда надоело вставлять руками, не чтобы «отдел сам поднял».
5. SQLite — только если оператору больно искать кейсы на диске. Не «когда появится второй пользователь».
6. Клиентские данные / DuckDB — как в PLAN v0.4, не раньше стабильной цитаты.

**Не делать:** форк Open WebUI, второй агент (LangGraph), Excel клиента в Knowledge, новая vector DB «вместо eval», развитие `frontend/`, IAM СВА в приложении.

## Итог

Проект не свалка скриптов. Есть продукт, инварианты, HITL, локальная модель, RAG с отказом и документация, с которой оператор садится рядом с аудитором.

Планка сеанса СВА: закрыта. Планка хоста в контуре банка: shared secret + пины образов. Планка «портал отдела» в это ревью не входит.
