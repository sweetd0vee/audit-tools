# Гайд: агент «Аудитор» в Open WebUI

Как аудитору вести проверку в чате: куда нажимать, что писать, что ответит система, что при этом видит языковая модель, и что делает код без модели.

Продуктовый вход — один адрес: [http://localhost:3000](http://localhost:3000).  
В новом чате выберите модель **Аудитор**. Не `qwen3.8:27b` и не любую модель с иконкой `ol` — это обычный чат без рук и без стоп-крана.

Поставить агент (один раз, админ): [`seed/openwebui/AGENT.md`](../seed/openwebui/AGENT.md).  
Настроить Open WebUI под качество (модели, RAG, Valves): [`OPENWEBUI.md`](OPENWEBUI.md).  
Краткая техническая шпаргалка фаз: [`AUDITOR.md`](AUDITOR.md).  
Как устроено саммари (в том числе на большой библиотеке): [`SAMMARI.md`](SAMMARI.md).  
API без чата: [`backend/README.md`](../backend/README.md).

Инвариант:

> Модель ускоряет поиск нормы и черновик обзора. Она не ставит аудиторское суждение и не заменяет чтение первоисточника. Цитата проверяется по файлу в кейсе.

Клиентские данные и формулировки проверки **не уходят в интернет**. Поиск актов — только по официальным доменам РБ.

## 1. Что это за агент

«Аудитор» — не ещё одна языковая модель в списке. Это **цикл с руками и стоп-краном**:

```
ваше сообщение
  → код понимает фазу (не свободный ReAct)
  → вызывает Audit Tool Server
  → если нужен человек — останавливается
  → иначе следующий шаг
  → ответ в чат
```

Локальная модель (`qwen3.8:27b` в Ollama) **не читает чат Open WebUI целиком**. Её вызывают точечно:

| Ваше сообщение | Модель вызывается? | Зачем |
|---|---|---|
| Описать проверку | да, один раз | JSON со списком НПА |
| `утверждаю 1, 2` / `плюс …` / `скачай` | нет | Код разбирает номера и качает файлы |
| `документы` / `статус` / `помощь` | нет | Код читает кейс |
| `саммари` | да, много раз | Карточка существенного на каждый акт + обзор проверки |
| `саммари total` | да, один раз | Конспект по теме **из знаний модели**, не из файлов кейса |
| `программа проверки` | да, один раз | Черновик программы аудиторской проверки банка РБ |
| `гипотезы` | да, один раз | Чеклист 8–10 гипотез проверки в Excel (xlsx) |
| `вопрос …` | да | Ответ **по найденным фрагментам** библиотеки |
| Обычный текст без команд | да | Диалог `POST /chat`, без цитат из кейса |

Пока вы не написали `утверждаю …`, ничего не скачивается. Качать или нет — решаете вы, не модель.

Одна проверка = один чат. Новая тема — новый чат и снова модель **Аудитор**.

## 2. Навигация в Open WebUI

Интерфейс может быть на русском или на английском. Ищите то же место по смыслу, если пункт называется иначе. Имя продукта в шапке — **Аудитор** (`WEBUI_NAME`).

### 2.1. Войти

1. Стек поднят: `docker compose up -d --build`.
2. Браузер: [http://localhost:3000](http://localhost:3000).
3. Войдите (первый запуск — создайте администратора).

Слева — лента чатов. Снизу слева — ваше имя. Справа — диалог.

### 2.2. Новый чат и выбор модели

1. Слева **Новый чат** / **New Chat**.
2. Над полем ввода (или в шапке) откройте **выбор модели**.
3. В поиске наберите `Аудитор`.
4. Выберите **Аудитор**. Иконка **не** `ol`.

`qwen3.8:27b` и остальные с `ol` — обычные модели Ollama. С ними нет кейса, нет «утверждаю», нет саммари.

Если «Аудитор» в списке нет — агент ещё не вставлен. Это делает администратор:

1. Имя внизу слева → **Панель администратора** / **Admin Panel**  
   (или сразу [http://localhost:3000/admin/functions](http://localhost:3000/admin/functions)).
2. Слева **Функции** / **Functions**. Pipe **нет** в Рабочем пространстве (там только Модели, Знания, Промпты, Скиллы, Инструменты).
3. Пошагово: [`AGENT.md`](../seed/openwebui/AGENT.md).

### 2.3. Куда писать

Большое поле внизу чата — единственный вход. Обычный текст, Enter отправляет.

Над ответом появляются **статусы** Pipe, например:

- «Смотрю, на каком вы шаге…»
- «Создаю проверку…»
- «Подбираю список документов (npa). Это может занять несколько минут…»
- «Сохраняю ваш выбор…»
- «Скачиваю выбранные документы…»
- «Готовлю базу знаний из скачанных документов…»
- «Ищу ответ в приложенных документах…»
- «Готовлю обзор базы знаний в Word. Это может занять несколько минут…»
- «Готовлю саммари total — конспект из знаний модели (не из базы)…»
- «Готовлю программу аудиторской проверки в Word. Это может занять несколько минут…»
- «Отвечаю как в обычном чате…»

Это не ответ модели, а прогресс. Список НПА и саммари занимают минуты, не секунды. Дождитесь конца шага.

В конец почти каждого ответа агент вшивает скрытую HTML-метку `<!--audit-case:a1b2c3-->`. В чате она обычно не видна. По ней следующие сообщения остаются в той же проверке. Если удалить ответы агента из истории — кейс «потеряется», и придётся описывать проверку заново.

Команды `помощь` / `help` / `?` показывают шпаргалку прямо в чате.

### 2.4. Чего не нажимать в этом сценарии

| Место в UI | Зачем оно в Open WebUI | Нужно ли здесь |
|---|---|---|
| **Рабочее пространство → Знания** / Workspace → Knowledge | Коллекции файлов для обычных моделей | Нет как основной путь. Агент сам индексирует кейс. Коллекция Knowledge создаётся только если в параметрах Pipe задан API-ключ |
| Скрепка / вложение файла | Прикрепить PDF к обычной модели | Не прикрепляйте клиентские Excel и договоры. Норма и факт смешаются |
| Веб-поиск в чате | Искать в интернете | Должен быть **выключен**. SearXNG работает только на сервере при скачивании актов |
| Выбор `qwen3.8:27b` вместо **Аудитор** | Голый чат | Агента нет |
| Тот же чат для второй проверки | История | Не делайте так. Новый чат |

### 2.5. Где потом взять файлы

Агент сам кладёт в ответ ссылки:

```
Скачать:
- архив документов (`…_npa.zip`): http://localhost:8100/api/v1/cases/{id}/library/archive
- обзор базы знаний (`…_summary.docx`): http://localhost:8100/api/v1/cases/{id}/knowledge/summary.docx
- саммари total (`…_total.docx`): http://localhost:8100/api/v1/cases/{id}/knowledge/total.docx
- программа проверки (`…_programma.docx`): http://localhost:8100/api/v1/cases/{id}/knowledge/program.docx
```

Zip — после скачивания актов. Word-обзор — после `саммари`. Total — после `саммари total`. Word-программа — после `программа проверки`. Открываются в браузере, не внутри чата.

Swagger [http://localhost:8100/docs](http://localhost:8100/docs) аудитору не нужен.

## 3. Кто на самом деле отвечает

Три слоя. Их полезно не путать, когда читаете ответ в чате.

```
Вы  →  Open WebUI (:3000)
         →  Pipe «Аудитор» (Python в Функциях)
              →  Audit Tool Server (:8100)
                   ├─ Ollama qwen3.8:27b              — список актов, карточки, total, программа, чат, ответ по фрагментам
                   ├─ Ollama qwen3-embedding:latest   — векторы чанков и вопроса
                   ├─ SearXNG                         — URL только по allowlist РБ
                   └─ диск                            — backend/data/audit_cases/{id}/
```

| Кто | Что делает | Чего не делает |
|---|---|---|
| **Вы** | Описываете проверку, утверждаете номера, читаете Word, сверяете цитату | Не обязаны знать JSON и API |
| **Pipe** | Понимает фазу **кодом**. Рисует статусы. Форматирует ответ в чат | Не «думает» о праве. Не вызывает модель на `утверждаю` / `документы` |
| **Audit Tool Server** | Система записи: кейс, кто выбран, что скачано, индекс, Word | Не рисует UI |
| **LLM (`qwen3.8:27b`)** | Предлагает список актов; пишет карточки, total и программу; отвечает по кускам на `вопрос`; болтает в обычном чате | Не решает, качать или нет. На `вопрос` видит только промпт с фрагментами, не весь кодекс |
| **Embedding** | Векторы для поиска похожих абзацев | Не генерирует текст |

Фраза «Аудитор ответил» почти всегда означает: **сначала код, потом (иногда) модель**. На шаге утверждения модель молчит.

## 4. История 1. Начать проверку

**Как аудитор.** На этой неделе проверка аренды коммерческой недвижимости: валютные расчёты, НДС, договоры с нерезидентами. Раньше вы вспоминали акты и искали редакции на pravo.by. Теперь открываете чат и одной строкой описываете проверку.

### Что сделать в UI

Новый чат → модель **Аудитор** → поле ввода.

### Что написать

Шаблон:

```
Проверка <тема>, <ключевое слово 1>, <слово 2>, <слово 3>
```

Текст **до первой запятой** станет названием проверки. Остальное через запятую — keywords для поиска и саммари.

Примеры:

```
Проверка аренды коммерческой недвижимости, аренда, валюта, НДС
```

```
Аудит кассовых операций, касса, лимит остатка, подотчёт
```

```
Проверка валютного контроля по экспортным контрактам, валютная выручка, срок репатриации
```

Не пишите JSON и не пишите «создай кейс». Не начинайте с `вопрос …` — агент не создаст проверку, а пойдёт в базу (её ещё нет). Обычный текст вроде «какой срок…» без кейса уйдёт в свободный чат, не создаст библиотеку.

Плохо: `аренда` (слишком коротко).  
Плохо: `вопрос Какой срок возврата валютной выручки?` (это вопрос к базе, кейса ещё нет).  
Плохо: `Какой срок возврата валютной выручки?` без кейса (обычный чат, библиотеки не будет).

### Что вы увидите

Статусы: «Создаю проверку…» → «Подбираю список документов (npa)…» (часто 1–3 минуты).

Потом нумерованный список:

```
Проверка: Проверка аренды коммерческой недвижимости
Ключевые слова: аренда, валюта, НДС

Предлагаю документы для базы знаний. Пока ничего не скачиваю — сначала выберите номера.

1. **Гражданский кодекс Республики Беларусь** — обязательно
   Зачем аудитору этот акт для данной проверки…
2. **Налоговый кодекс …** — обязательно
3. **Инструкция НБРБ …** — желательно
…

Напишите, какие взять, например: `утверждаю 1, 2, 4`
Или: `утверждаю все обязательные`.
Нет в списке — допишите названия: `утверждаю 1, 2 плюс Инструкция НБРБ № 38; Положение о внутреннем контроле`.
Если знаете ссылку на документ: `к 3 url https://pravo.by/document/?guid=…`
```

Приоритеты: **обязательно** / **желательно** / **опционально**. Список можно урезать. Модель могла предложить лишний или устаревший акт — вы человек в контуре.

### Под капотом

1. Pipe видит, что в чате **ещё нет** кейса и текст похож на проверку (`проверк` / `аудит` / `аренда` / `кредит` / `валют` / `касс` / `нпа`) или название длиннее 12 символов.
2. `POST /api/v1/cases` — на диске появляется папка кейса.
3. `POST /api/v1/cases/{id}/propose` — сервер собирает промпт методолога и вызывает Ollama.

**Что получает LLM.** Системная роль: старший методолог внутреннего аудита банка РБ. Правила: только законодательство / НПА / инструкции НБРБ / акты Минфина и МНС; без методичек блогов; не выдумывать номера статей как факт; ответ **только JSON без markdown**.

Пользовательский промпт: название проверки, keywords, период. Просят JSON вида `topics` + `documents[]` с полями `title`, `doc_type`, `why_needed`, `search_queries` (`site:pravo.gov.by …`), `priority` 1/2/3. Нужно примерно 8–15 актов.

**Что отвечает LLM.** Не текст в чат, а JSON. Pipe его **не показывает сырьём**: нумерует с 1, переводит priority в «обязательно / желательно / опционально», вшивает `<!--audit-case:…-->`. Файлы ещё не качаются. Поисковые запросы модели уходят в download позже.

## 5. История 2. Утвердить и скачать

**Как аудитор.** Вы пробежали список: ГК и НК берёте, инструкцию НБРБ тоже, методичку с приоритетом 3 пропускаете. На один акт уже открыта вкладка pravo.by.

### Что написать

Часть списка:

```
утверждаю 1, 2, 4
```

Синонимы: `подтверждаю`, `выбираю`, `скачивай`, `скачай`, `бери эти акты`.

Только обязательные (не «все из списка»):

```
утверждаю все обязательные
```

Подложить официальную ссылку. URL **целиком** из адресной строки, без многоточия `...`:

```
утверждаю 1, 2, 4, к 4 url https://pravo.by/document/?guid=3871&p0=Hk9900218
```

Только ссылка к пункту:

```
к 3 url https://pravo.by/document/?guid=…
```

Домены allowlist: `pravo.by`, `pravo.gov.by`, `etalonline.by`, `nbrb.by`, `minfin.gov.by`, `nalog.gov.by`, `government.by`, `president.gov.by`.

Не качать: напишите, чего не хватает, **без** слов «утверждаю / скачай». Если список совсем не тот — новый чат и точнее keywords.

### Что вы увидите

Статусы: «Сохраняю ваш выбор…» → «Скачиваю выбранные документы…» → «Готовлю базу знаний из скачанных документов…» (и при наличии ключа — «Добавляю документы в базу знаний чата…»).

Потом:

```
Готово. Скачано документов: 4. В базе знаний N документов.

Скачать:
- архив документов (`…_npa.zip`): http://localhost:8100/api/v1/cases/…/library/archive

Дальше:
— `программа проверки` — программа проверки в Word;
— `саммари` — основная информация по теме из базы знаний в Word;
— `саммари total` — основная информация по теме из знаний модели;
— `гипотезы` — чеклист гипотез проверки в Excel;
— `вопрос` — вопрос по базе знаний (например `вопрос Какой срок…`);
— `документы` — посмотреть список документов в базе знаний;
— обычный диалог — пишите без префикса.
```

Если часть не скачалась — список названий и подсказка `скачай` или `к N url …`.

### Под капотом

LLM **не вызывается**. Pipe разбирает номера (`1` = первый в последнем списке) или короткий id акта.

1. `GET /api/v1/cases/{id}` — текущий список.
2. `POST …/select` — помечает выбранные; `manual_urls`, если дали ссылку.
3. `POST …/download` — для каждого акта URL в порядке: ваша ссылка → curated `known_sources` (известные официальные URL по названию) → SearXNG строго по allowlist.
4. HTML/PDF → `knowledge_raw/` → текст в `knowledge_text/` → чанки (в т.ч. по статьям) → embeddings → `knowledge_index.json`.
5. Опционально sync `.txt` в коллекцию Knowledge Open WebUI.

Уже скачанный файл повторно не трогается.

## 6. История 3. Акта нет в списке

**Как аудитор.** Модель не предложила нужную инструкцию НБРБ. Вы знаете точное название.

### Что написать

Вместе с номерами:

```
утверждаю 1, 2 плюс Инструкция НБРБ № 38; Положение о внутреннем контроле
```

Только название (к уже выбранным):

```
добавь Инструкция о порядке проведения валютных операций
```

Синонимы-разделители: `плюс`, `добавь`, `дополнительно`, `и ещё`, `+`. Несколько названий — через `;` или `+`.

### Что вы увидите

Статус «Ищу документы по вашим названиям…», затем в ответе блок:

```
Добавлены по вашему названию (ищу официальный текст):
- Инструкция НБРБ № 38
```

Дальше тот же download, что в истории 2. Если URL не нашёлся — как в истории 4: `скачай` или полная ссылка.

### Под капотом

LLM снова **не вызывается**. Pipe вырезает хвост после `плюс` / `добавь`, кладёт названия в `extra_titles` на `POST …/select`. Сервер добавляет пункты в список кейса и ищет URL тем же порядком: known_sources → SearXNG.

## 7. История 4. Акт не скачался

**Как аудитор.** В ответе «скачано 4, не скачалось: 1» и название. SearXNG часто ловит 403 с поисковиков — это ожидаемо, не «агент сломался».

### Что написать

Повторить уже утверждённые (лежащее не перезапишет):

```
скачай
```

или `скачай ещё раз`.

Подложить URL на провалившийся пункт:

```
к 7 url https://nbrb.by/legislation/documents/полный-путь
```

Посмотреть состав библиотеки:

```
документы
```

Синонимы: `библиотека`, `файлы`, `архив`, `покажи акты`.

### Что вы увидите

Список: название — «скачан» / «не скачался», плюс ссылка на zip.

Проверьте zip глазами: там должны быть **утверждённые** вами акты, а не «то, что модель вспомнила».

Если URL с `...` или `…` — агент ответит, что ссылка обрезана, и не качнёт.

### Под капотом

`документы` → `GET …/library`. Повтор `скачай` без новых номеров берёт уже выбранные id и снова гоняет download. LLM не участвует.

## 8. История 5. Саммари в Word

**Как аудитор.** Библиотека скачана. Читать ГК целиком не хотите: нужен обзор на несколько страниц со ссылками на статьи.

### Что написать

```
саммари
```

Синонимы: `сводка`, `бриф`, `docx`, `word`, `обзор актов`, `файл word`.

Пересобрать после докачки актов:

```
саммари заново
```

Повтор без `заново` отдаст уже готовый файл, если состав библиотеки не менялся.

Не путать с вопросом про статью: `вопрос статья 625 ГК?` — это вопрос к базе, не сборка Word. Без слова `вопрос` фраза про статью может уйти в обычный чат.

### Что вы увидите

Статус «Готовлю обзор базы знаний в Word…», затем по актам статусы со стрима (например «Саммари акта 3 из 10: …», «Пишу обзор проверки…»). Несколько минут.

В чат **полный Word не копируется**:

```
Обзор базы знаний готов. Скачайте Word и читайте сами — в чат полный текст не копирую.

Скачать:
- архив документов (`…_npa.zip`): …
- обзор базы знаний (`…_summary.docx`): http://localhost:8100/api/v1/cases/…/knowledge/summary.docx

Кратко по документам:
- Гражданский кодекс …: …
```

В файле:

- обзор нормативного контура проверки;
- карточка по каждому скачанному акту (зачем нужен, ключевые нормы, что смотреть, пробелы);
- приложение: фрагменты `[n]` со статьёй/пунктом и официальным URL.

Номера `[n]` в тексте — **не** статьи закона, а ссылки на фрагменты в конце файла. Статья указана рядом с фрагментом. Это черновик для чтения глазами, не мнение аудитора.

### Под капотом

`GET /api/v1/cases/{id}/knowledge/brief/stream` (при `заново` — `?force=true`).

Для каждого скачанного акта:

1. Короткий акт — один вызов: карточка существенного под эту проверку.
2. Длинный акт — **query-focused RAG**: hybrid BM25+эмбеддинги → RRF → MMR → один stuff-вызов по фрагментам (не map-reduce по всему кодексу).
3. Затем вызов обзора по карточкам.

Карточка: зачем акт в этой проверке, суть и сфера, 5–15 ключевых норм, что проверять, чего нет в выборке.

Word и Markdown пишутся в `summaries/`. Чат получает ссылку и дайджест. Смена схемы карточки пересобирает Word при следующем `саммари`.

Акты идут по одному. Один длинный акт ≈ **1 вызов модели** (плюс эмбеддинги). Подробно: [`SAMMARI.md`](SAMMARI.md).

## 8а. История 5а. Программа проверки в Word

**Как аудитор.** Библиотека собрана (или хотя бы есть название проверки и keywords). Нужен не обзор актов, а **программа аудиторской проверки**: цель, границы, риски, процедуры, что запросить у банка, критерии по праву РБ.

### Что написать

```
программа проверки
```

Синонимы: `программу проверки`, `программа аудиторской проверки`, `составь программу`, `сделай программу`.

Пересобрать:

```
программа проверки заново
```

Повтор без `заново` отдаст уже готовый файл, если название, keywords и состав библиотеки не менялись.

Фраза должна быть именно про программу. Не пишите «Программа проверки аренды, аренда, НДС» как первую реплику нового чата — агент может принять это за название новой проверки. Сначала создайте кейс шаблоном из истории 1, затем отдельно: `программа проверки`.

### Что вы увидите

Статус «Готовлю программу аудиторской проверки в Word…». Обычно один длинный вызов модели, несколько минут.

В чат **полный Word не копируется**:

```
Программа аудиторской проверки готова. Скачайте Word и правьте сами — в чат полный текст не копирую. Это черновик, не утверждённая программа СВА.

Скачать:
- архив документов (`…_npa.zip`): …
- программа проверки (`…_programma.docx`): http://localhost:8100/api/v1/cases/…/knowledge/program.docx
```

В файле:

- общие сведения, цель и задачи;
- объект, границы, период;
- нормативные критерии из названия проверки, keywords и приложенных актов;
- существенные риски;
- аудиторские процедуры (что запросить, как проверить, критерий, рабочий документ);
- выборка, рабочие документы, ограничения черновика;
- приложение: фрагменты `[n]`, если акты уже скачаны.

Это черновик для службы внутреннего аудита банка РБ. Не подпись руководителя СВА и не вывод «нарушение / не нарушение».

### Под капотом

`GET …/knowledge/program/stream` (при `заново` — `?force=true`).

Один вызов LLM. В промпт кладут: название проверки, keywords, период, каталог утверждённых/скачанных/приложенных документов, релевантные фрагменты НПА с номерами `[n]`, уже готовые карточки саммари — если они есть.

**Что получает LLM.** Системная роль: внутренний аудитор банка РБ, сотрудник СВА. Задача — черновик программы проверки, не акт. Только право РБ (кодексы, законы, инструкции НБРБ, акты Минфина и МНС). Не подменять РФ/ЕС/IFRS. Не выдумывать номера статей: после нормы — `[n]` из списка фрагментов. Нет фрагмента — процедура на уровне направления и пометка «критерий уточнить по первоисточнику».

**Что отвечает LLM.** Markdown с фиксированными разделами. Pipe собирает Word и в чат кладёт ссылку, не полный текст.

## 9. История 6. Спросить норму

**Как аудитор.** Word прочитан, в программу проверки нужна конкретная норма: валютная оговорка в договоре с резидентом.

### Что сделать в UI

Пишите **в том же чате**, где создали проверку. Новый чат = пустая библиотека.

Чтобы ответ шёл **из базы знаний**, сообщение **должно начинаться** со слова `вопрос` (или `/ask`, `/вопрос`). Без этого префикса Pipe отправит текст в обычный чат: модель ответит «из головы», блока цитат не будет — это не норма.

### Что написать

```
вопрос Можно ли в договоре аренды с резидентом РБ устанавливать арендную плату в евро?
```

```
вопрос Какой срок возврата валютной выручки по аренде нерезиденту?
```

```
вопрос Какая статья НК регулирует НДС при сдаче в аренду нежилого помещения?
```

```
вопрос Где в ГК сказано про государственную регистрацию договора аренды недвижимости?
```

Как помочь поиску: назовите предмет («аренда нежилого», «валютная оговорка»); если знаете акт — скажите («в инструкции 38», «по НК»). Один вопрос за сообщение.

Плохо: `Можно ли в договоре …?` без слова `вопрос` — это обычный чат, не цитата.  
Плохо: `вопрос Расскажи всё про аренду` (слишком широко).  
Плохо: `вопрос Сравни с Россией и IFRS` (в библиотеке этого нет).  
Плохо: `вопрос Сколько начислено аренды по договору №17?` (это **факт** из клиентских данных; контура фактов ещё нет).

### Что вы увидите

Статус: «Ищу ответ в приложенных документах…»

Потом текст ответа и блок:

```
**Откуда в базе знаний:**
- Гражданский кодекс …: дословный обрезок фрагмента…
```

Если фрагментов нет — в блоке будет: «В приложенных документах этого не нашлось — не опирайтесь на ответ как на факт из базы.» **Не считайте ответ нормой**, если цитат нет. Переформулируйте с названием акта или утвердите недостающий документ (`плюс …` / `скачай`).

### Под капотом

`POST …/knowledge/ask` с текстом **после** слова `вопрос`.

1. Вопрос эмбеддится `qwen3-embedding:latest` (та же модель, что строила индекс).
2. Чанки ранжируются: пересечение слов + cosine. Берётся top-k (по умолчанию 8).
3. Эти куски кладутся в промпт. **Веб-поиска на этом шаге нет.**

**Что получает LLM.** Системная роль: ассистент внутреннего аудитора банка РБ; опираться **в первую очередь** на фрагменты; цитировать документ и статью/пункт; нет ответа во фрагментах — так и сказать (можно общую оговорку из своих знаний, явно пометив «не из базы НПА»); не выдумывать номера норм.

Пользовательский блок: тема проверки, keywords, ваш вопрос, пронумерованные куски `[1] Название акта + текст`.

**Что отвечает LLM.** Текст по-русски. Pipe **дописывает** блок «Откуда в базе знаний» из тех же чанков (обрезки до ~220 символов) — даже если модель ответила гладко. Источник истины для вас — блок цитат и файл в zip, не красноречие абзаца.

Модель видит только top-k. Если нужная статья не попала в выборку — её «нет», хотя файл лежит в кейсе. Тогда сузьте вопрос или укажите акт.

Вопрос в продукте идёт через Pipe → `/knowledge/ask` сервера, а не через «прикрепить Knowledge к обычной модели». Коллекция Open WebUI — опциональный дубль `.txt`, если задан API-ключ.

## 10. История 7. Новая проверка

**Как аудитор.** Аренду закрыли, дальше касса.

Не пишите «Проверка кассовых…» в старом чате: без префикса это уйдёт в **обычный диалог** того же кейса и не создаст новую библиотеку. Новый кейс Pipe создаёт только если в этом окне **ещё нет** метки проверки.

## 11. Шпаргалка фраз

| Написать | Зачем | LLM вызывается? |
|---|---|---|
| `Проверка …, слово, слово` | Создать кейс и получить список актов | да, propose |
| `утверждаю 1, 2, 4` | Выбрать и скачать | нет |
| `утверждаю все обязательные` | Только priority=1 | нет |
| `утверждаю 1, 2 плюс Инструкция …` | Номера + акт, которого не было в списке | нет |
| `добавь Положение о …` | Дописать название к уже выбранным | нет |
| `к 3 url https://…` | Подложить официальную ссылку | нет |
| `скачай` | Повторить download выбранных | нет |
| `документы` | Состав библиотеки и zip | нет |
| `саммари` / `саммари заново` | Word-обзор актов из библиотеки | да |
| `саммари total` / `конспект модели` | Word-конспект из знаний модели, не из файлов | да |
| `программа проверки` / `… заново` | Word-программа аудиторской проверки | да |
| `гипотезы` / `… заново` | Excel-чеклист 8–10 гипотез проверки | да |
| `вопрос …` / `/ask …` | Норма из индекса кейса + блок цитат | да, ask |
| любой другой текст в чате с кейсом | Обычный диалог, не цитата | да, chat |
| `статус` | Состояние текущего кейса | нет |
| `кейсы` / `проверки` | Список кейсов на сервере | нет |
| `помощь` / `help` / `?` | Шпаргалка в чате | нет |

Как Pipe выбирает фазу (первое совпадение побеждает):

1. пусто / `помощь` / `?` → шпаргалка;
2. сообщение начинается с `вопрос` / `/ask` → ask по индексу;
3. `программа проверки` / `составь программу` → Word-программа;
4. `саммари total` / `конспект модели` → Word-конспект из знаний модели;
5. `гипотезы` / `чеклист гипотез` → Excel-чеклист;
6. `саммари` / `сводка` / `бриф` / `docx` → Word-обзор актов;
7. `утверждаю` / `скачай` / `к 3 url …` / `плюс …` / `добавь …` → select + download;
8. `документы` / `библиотека` → список файлов;
9. `статус` / `кейсы` → состояние;
10. текста хватает на новую проверку **и в чате ещё нет кейса** → create + propose;
11. иначе → обычный чат (`POST /chat`).

Поэтому «Какой срок…?» без слова `вопрос` — не цитата. «Проверка аренды…» во **уже живом** чате не создаст второй кейс, а уйдёт в диалог. Новая проверка — новый чат.

## 12. Что видит и отвечает LLM

Полные тексты промптов (их можно править): [PROMPTS.md](PROMPTS.md) и файлы в [`prompts/`](prompts/).

Модель **не видит** диалог Open WebUI как историю GPT на шагах propose / ask / саммари / программа / total. Обычный чат — исключение: туда уходит обрезанная история user/assistant (без метки кейса и блока цитат), последние 24 реплики. Температура на сервере низкая (0.1–0.2).

### Предложить акты (`propose`)

| | |
|---|---|
| Роль | Старший методолог ВА банка РБ |
| Вход | Название проверки + keywords |
| Выход модели | JSON (topics, documents) |
| Что видит аудитор | Нумерованный список, просьба утвердить |
| Веб | Нет |

### Ответ по норме (`ask`)

| | |
|---|---|
| Роль | Ассистент внутреннего аудитора РБ |
| Вход | Вопрос после префикса `вопрос` + top-k чанков из **скачанной** библиотеки |
| Выход модели | Текст по фрагментам |
| Что видит аудитор | Текст + блок **Откуда в базе знаний** (его дописывает Pipe) |
| Веб | Нет |

Если чанков нет (ещё не скачали) — ошибка «база знаний пуста», модель не вызывается.

### Карточка акта и обзор (`саммари`)

| | |
|---|---|
| Роль | Старший аудитор; карточка существенного для этой проверки, не дамп статей |
| Вход на акт | Название проверки + keywords; короткий акт — полный текст, длинный — RAG-фрагменты |
| Вход на обзор | Все карточки + keywords |
| Выход модели | Карточка: зачем акт, суть, ключевые нормы, что проверять, чего нет |
| Что видит аудитор | Ссылка на Word + короткий дайджест |

Подробно (в том числе много актов и кодексы): [SAMMARI.md](SAMMARI.md).

### Программа проверки (`программа проверки`)

| | |
|---|---|
| Роль | Внутренний аудитор банка РБ, сотрудник СВА; черновик программы, не акт |
| Вход | Название проверки, keywords, каталог приложенных актов, фрагменты `[n]`, карточки саммари если уже есть |
| Выход модели | Markdown программы (цель, риски, процедуры, выборка) |
| Что видит аудитор | Ссылка на Word + краткий список процедур |
| Веб | Нет |

### Total саммари (`саммари total`)

| | |
|---|---|
| Роль | Внутренний аудитор РБ; конспект из обучения модели |
| Вход | Название проверки + keywords, **без** файлов кейса |
| Выход модели | Markdown с разделами и `[n]` |
| Что видит аудитор | Ссылка на Word |
| Веб | Нет |

### Обычный чат (без префикса)

| | |
|---|---|
| Роль | Помощник ВА; не суждение |
| Вход | История чата (очищенная) |
| Выход модели | Связный ответ |
| Что видит аудитор | Текст **без** блока «Откуда в базе знаний» |
| Веб | Нет |

### Когда модель молчит

Утверждение, `плюс` / `добавь`, скачивание, `документы`, `статус`, `помощь` — чистый код. «Галлюцинация статьи» на этих шагах невозможна: текста модели нет.

## 13. Карта под капотом

```
Вы (браузер :3000)
    │  обычные сообщения
    ▼
Pipe «Аудитор»          Python, Админ → Функции, файл seed/openwebui/functions/audit_agent.py
    │  фаза КОДом, HITL: download только после «утверждаю»
    ▼
Audit Tool Server       FastAPI :8100
    ├─ Ollama           qwen3.8:27b — propose, карточки, total, программа, чат, ask
    ├─ Ollama embed     qwen3-embedding:latest — векторы
    ├─ SearXNG          URL только по allowlist РБ
    └─ диск             backend/data/audit_cases/{case_id}/
```

Почему Pipe, а не «просто Qwen в чате»: локальная 27B плохо держит native tool-calling и может вызвать download без вашего «утверждаю». Фазу выбирает код.

### Папка кейса

```
backend/data/audit_cases/{case_id}/
  case.json               система записи: статус, кто выбран, URL
  manifest.json           что скачали, sha256, источник URL
  knowledge_raw/          первоисточники (html/pdf)
  knowledge_text/         очищенный текст
  summaries/              карточки актов + Word-обзор + brief.md
  totals/                 саммари total (из знаний модели)
  programs/               Word-программа проверки + program.md
  knowledge_index.json    чанки для вопросов
  library.zip             архив сырых файлов
```

### Норма ≠ факт

| | Норма (сейчас) | Факт (план) |
|---|---|---|
| Что | НПА, инструкции НБРБ | Выгрузки, договоры, обороты |
| Откуда ответ | RAG по библиотеке кейса (`вопрос …` → `POST …/knowledge/ask`) | SQL / tools по файлам клиента |
| Нельзя | Сочинять статью | Класть Excel в ту же Knowledge |

## 14. Чего агент не делает

- не ставит вывод «нарушение / не нарушение»;
- не подписывает working paper;
- не ищет по всему интернету;
- не качает акт, пока вы не утвердили номер, не дали название (`плюс`) или URL;
- не считает ответ нормой, если блока цитат нет (в том числе обычный чат без `вопрос`);
- не ведёт две проверки в одном чате;
- не отвечает по суммам договора и выгрузкам клиента (этого контура ещё нет).

## 15. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| В списке моделей нет «Аудитор» | Админ: Функции, ID `auditor`, переключатель **Включено**, F5. [`AGENT.md`](../seed/openwebui/AGENT.md) |
| Отвечает «голый» Qwen, без списка актов | В шапке чата выбрана не модель **Аудитор** |
| «В этом чате ещё нет проверки» | Опишите проверку заново **в этом** окне; не удаляйте ответы агента с меткой кейса |
| «Не поняла, какие документы взять» | `утверждаю 1, 2` — номера как в последнем списке |
| Нужного акта нет в списке | `утверждаю 1, 2 плюс Полное название акта` |
| «Ссылка обрезана» | URL из адресной строки, без `...` |
| Акт не скачался | `скачай` или `к N url https://…` |
| «Сервер проверки не отвечает» | Compose: контейнер `audit-tools` жив; параметры Pipe: `AUDIT_API=http://backend:8100` |
| Саммари долго / таймаут | Подождите; в параметрах Pipe `BRIEF_TIMEOUT_SEC`; повтор `саммари` |
| Total саммари долго / таймаут | Тот же `BRIEF_TIMEOUT_SEC`; повтор `саммари total` |
| Программа проверки долго / таймаут | Тот же `BRIEF_TIMEOUT_SEC`; повтор `программа проверки` |
| Ответ гладкий, но блока «Откуда в базе» нет | Нет префикса `вопрос`. Напишите `вопрос …` |
| Ответ без цитат / «этого нет» | Акта нет в библиотеке или вопрос слишком общий. Утвердите акт или сузьте `вопрос …` |
| Модель выдумала РФ / IFRS | В библиотеке этого нет; не принимайте. Спросите с указанием акта РБ |
| Выбрали обычный Qwen | Чат без HITL. Переключите модель на **Аудитор** |

Разработчикам: как устроен retrieval — [`RAG_для_разработчика.md`](RAG_для_разработчика.md). Фазы Pipe одной таблицей — [`AUDITOR.md`](AUDITOR.md).
