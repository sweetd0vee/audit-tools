# Гайд: агент «Аудитор» в Open WebUI

Как аудитору банка вести проверку в чате: куда нажимать, что писать, что ответит система, что при этом видит языковая модель, и что происходит без вашего участия.

Продуктовый вход — один адрес: [http://localhost:3000](http://localhost:3000).  
Модель в новом чате: **Аудитор**. Не `qwen3.6:35b` и не любая модель с иконкой `ol` — это обычный чат без рук и без стоп-крана.

Поставить агент в Admin (один раз): [`seed/openwebui/AGENT.md`](../seed/openwebui/AGENT.md).  
Техническая шпаргалка фаз Pipe: [`AUDITOR.md`](AUDITOR.md).  
API без чата: [`backend/README.md`](../backend/README.md).

Инвариант:

> Модель ускоряет поиск нормы и черновик обзора. Она не ставит аудиторское суждение и не заменяет чтение первоисточника. Цитата проверяется по файлу в кейсе.

## 1. Что это за агент

«Аудитор» — не ещё одна языковая модель в списке. Это **цикл с руками и стоп-краном**:

```
ваше сообщение
  → код понимает фазу (не свободный ReAct)
  → вызывает Audit Tool Server
  → если нужен человек — останавливается
  → иначе следующий шаг
  → ответ в чат
```

Локальная модель (`qwen3.6:35b` в Ollama) **не читает ваш чат целиком**. Её вызывают точечно:

| Шаг | Модель вызывается? | Зачем |
|---|---|---|
| Описать проверку | да | Предложить JSON со списком НПА |
| `утверждаю 1, 2` | нет | Код разбирает номера и качает файлы |
| `документы` / `статус` | нет | Код читает папку кейса |
| `саммари` | да, много раз | Карточка на каждый акт + обзор проверки |
| Вопрос по норме | да | Ответ **только** по найденным фрагментам |

Пока вы не написали `утверждаю …`, ничего не скачивается. Это стоп-кран: качать или нет — решаете вы, не модель.

Одна проверка = один чат. Новая тема — новый чат и снова модель **Аудитор**.

Клиентские данные и формулировки проверки **не уходят в интернет**. Поиск актов — только по официальным доменам РБ (`pravo.by`, `nbrb.by` и остальные из allowlist).

## 2. Навигация в Open WebUI

Интерфейс может быть на русском или на английском. Ниже — оба варианта. Ищите то же место по смыслу, если пункт называется иначе.

### 2.1. Войти

1. Compose уже поднят: `docker compose up -d --build`.
2. Браузер: [http://localhost:3000](http://localhost:3000).
3. Войдите (первый запуск — создайте администратора).

Слева — лента чатов. Снизу слева — ваше имя (например, **Arina**). Справа — область диалога.

### 2.2. Новый чат и выбор модели

1. Слева нажмите **Новый чат** / **New Chat** (плюс или кнопка вверху списка).
2. Над полем ввода (или в шапке чата) откройте **выбор модели**.
3. В поиске моделей наберите `Аудитор`.
4. Выберите **Аудитор**. Иконка **не** `ol`.  
   `qwen3.6:35b` и остальные с `ol` — обычные модели Ollama. С ними агента нет: нет кейса, нет «утверждаю», нет саммари.

Если «Аудитор» в списке нет — агент ещё не вставлен. Это делает администратор: имя внизу слева → **Панель администратора** / **Admin Panel** → **Функции** / **Functions**. Пошагово: [`AGENT.md`](../seed/openwebui/AGENT.md).

### 2.3. Куда писать

Большое поле внизу чата — единственный вход. Пишите обычным текстом, Enter отправляет.

Над ответом (или под полем ввода) появляются **статусы** агента, например:

- «Смотрю, на каком вы шаге…»
- «Подбираю список документов. Это может занять несколько минут…»
- «Скачиваю выбранные документы…»
- «Ищу ответ в приложенных документах…»

Это не ответ модели, а прогресс Pipe. Дождитесь конца шага — список НПА и саммари занимают минуты, не секунды.

В конце почти каждого ответа агент вшивает скрытую метку `<!--audit-case:……-->`. Её не нужно копировать и не нужно стирать из истории: по ней следующие сообщения остаются в той же проверке. Если удалить ответы агента из чата — кейс «потеряется», и придётся описывать проверку заново.

### 2.4. Чего не нажимать в этом сценарии

| Место в UI | Зачем оно в Open WebUI | Нужно ли аудитору «Аудитора» |
|---|---|---|
| **Рабочее пространство → Знания** / Workspace → Knowledge | Коллекции файлов для обычных моделей | Нет как основной путь. Агент сам кладёт документы в индекс кейса. Коллекция Knowledge создаётся только если в Valves задан API-ключ |
| Скрепка / вложение файла в чат | Прикрепить PDF к обычной модели | Не прикрепляйте клиентские Excel и договоры. Норма и факт смешаются |
| Веб-поиск в чате | Искать в интернете | Должен быть **выключен**. SearXNG работает только на стороне сервера при скачивании актов |
| Выбор `qwen3.6:35b` вместо **Аудитор** | Голый чат | Агента нет |
| Тот же чат для второй проверки | История | Не делайте так. Новый чат |

### 2.5. Где потом взять файлы

Агент сам кладёт в ответ ссылки вида:

```
http://localhost:8100/api/v1/cases/{id}/library/archive
http://localhost:8100/api/v1/cases/{id}/knowledge/brief.docx
```

Первая — zip скачанных актов. Вторая — Word-обзор после команды `саммари`. Открываются в браузере, не внутри чата.

Swagger [http://localhost:8100/docs](http://localhost:8100/docs) аудитору не нужен.

## 3. Кто на самом деле отвечает

Три слоя. Их полезно не путать, когда читаете ответ в чате.

```
Вы  →  Open WebUI (:3000)
         →  Pipe «Аудитор» (Python в Functions)
              →  Audit Tool Server (:8100)
                   ├─ Ollama qwen3.6:35b     — список актов, карточки, ответ по фрагментам
                   ├─ Ollama qwen3-embedding — векторы чанков и вопроса
                   ├─ SearXNG                — поиск URL только по allowlist РБ
                   └─ диск кейса             — backend/data/audit_cases/{id}/
```

| Кто | Что делает | Чего не делает |
|---|---|---|
| **Вы** | Описываете проверку, утверждаете номера, читаете Word, сверяете цитату | Не обязаны знать JSON и API |
| **Pipe** | Понимает фазу **кодом** (регулярки и порядок if). Рисует статусы. Форматирует ответ в чат | Не «думает» о праве. Не вызывает модель на `утверждаю` / `документы` |
| **Audit Tool Server** | Система записи: кейс, кто выбран, что скачано, индекс, Word | Не рисует UI |
| **LLM (qwen3.6:35b)** | Предлагает список актов; пишет карточки и обзор; отвечает на вопрос **по подложенным кускам** | Не решает, качать или нет. Не видит весь кодекс, только то, что попало в промпт |
| **Embedding** | Считает векторы для поиска похожих абзацев | Не генерирует текст |

Поэтому фраза в чате «Аудитор ответил» почти всегда означает: **сначала код, потом (иногда) модель**. На шаге утверждения модель молчит.

## 4. История 1. Начать проверку

**Как аудитор.** На этой неделе проверка аренды коммерческой недвижимости: валютные расчёты, НДС, договоры с нерезидентами. Раньше вы вспоминали акты и искали редакции на pravo.by. Теперь открываете чат и одной строкой описываете проверку.

### Что сделать в UI

Новый чат → модель **Аудитор** → поле ввода.

### Что написать

Шаблон:

```
Проверка <тема>, <ключевое слово 1>, <слово 2>, <слово 3>
```

Текст **до первой запятой** станет названием проверки. Остальное через запятую — keywords для поиска и саммари.

Примеры:

```
Проверка аренды коммерческой недвижимости, аренда, валюта, НДС
```

```
Аудит кассовых операций, касса, лимит остатка, подотчёт
```

```
Проверка валютного контроля по экспортным контрактам, валютная выручка, срок репатриации
```

Не пишите JSON и не пишите «создай кейс». Не начинайте с вопроса («какой срок…») — агент не создаст проверку, а попытается ответить (и кейса ещё нет).

Плохо: `аренда` (слишком коротко).  
Плохо: `Какой срок возврата валютной выручки?` (это вопрос).

### Что вы увидите

Статусы: «Создаю проверку…» → «Подбираю список документов…» (1–3 минуты).

Потом нумерованный список, например:

```
Проверка: Проверка аренды коммерческой недвижимости
Ключевые слова: аренда, валюта, НДС

Предлагаю документы для базы знаний. Пока ничего не скачиваю — сначала выберите номера.

1. Гражданский кодекс Республики Беларусь — обязательно
   Зачем аудитору этот акт для данной проверки…
2. Налоговый кодекс … — обязательно
3. Инструкция НБРБ … — желательно
…

Напишите, какие взять, например: утверждаю 1, 2, 4
```

Приоритеты: **обязательно** / **желательно** / **опционально**. Список можно урезать. Модель могла предложить лишний или устаревший акт — вы человек в контуре.

### Под капотом

1. Pipe видит, что текст похож на проверку (`проверк` / `аудит` / `аренда` / …) и **не** похож на вопрос.
2. `POST /api/v1/cases` — на диске появляется папка кейса.
3. `POST …/propose` — сервер собирает промпт методолога и вызывает Ollama.

**Что получает LLM.** Системная роль: старший методолог внутреннего аудита банка РБ. В пользовательском сообщении — название проверки, keywords, период. Просят **только JSON** (без markdown): темы, список документов с `title`, `doc_type`, `why_needed`, поисковыми запросами `site:pravo.gov.by …`, `priority` 1/2/3. Около 8–15 актов. Запрещено выдавать номера статей как факт.

**Что отвечает LLM.** Не текст в чат, а JSON. Pipe этот JSON **не показывает сырьём**: нормализует поля, нумерует с 1, переводит priority в «обязательно / желательно / опционально», вшивает метку кейса. Файлы ещё не качаются. Поисковые запросы модели уходят в download позже, не в ваш ответ.

## 5. История 2. Утвердить документы и скачать

**Как аудитор.** Вы пробежали список глазами: ГК и НК берёте, инструкцию НБРБ тоже, методичку с приоритетом 3 пропускаете. На один акт уже открыта вкладка pravo.by.

### Что написать

Часть списка:

```
утверждаю 1, 2, 4
```

Синонимы: `подтверждаю`, `выбираю`, `скачивай`, `скачай`, `бери эти акты`.

Только обязательные (не «все из списка»):

```
утверждаю все обязательные
```

Подложить официальную ссылку. URL **целиком** из адресной строки, без многоточия `...`:

```
утверждаю 1, 2, 4, к 4 url https://pravo.by/document/?guid=3871&p0=Hk9900218
```

Только ссылка (докачать уже выбранные + этот URL):

```
к 3 url https://pravo.by/document/?guid=…
```

Домены allowlist: `pravo.by`, `pravo.gov.by`, `etalonline.by`, `nbrb.by`, `minfin.gov.by`, `nalog.gov.by`, `government.by`, `president.gov.by`.

Не качать: напишите, чего не хватает, **без** слов «утверждаю / скачай». Если список совсем не тот — новый чат и точнее keywords.

### Что вы увидите

Статусы: «Сохраняю ваш выбор…» → «Скачиваю…» → «Готовлю базу знаний…» (и при наличии ключа Open WebUI — «Добавляю документы в базу знаний чата…»).

Потом:

```
Готово. Скачано документов: 4. В базе знаний N документов.

Скачать:
- архив документов (…_npa.zip): http://localhost:8100/api/v1/cases/…/library/archive

Дальше можно задавать вопросы по базе знаний.
Чтобы получить краткий обзор в Word, напишите саммари.
```

Если часть не скачалась — список названий и подсказка `скачай` или `к N url …`.

### Под капотом

LLM **не вызывается**. Pipe разбирает номера (`1` = первый в последнем списке) или hex-id акта.

1. `GET …/cases/{id}` — текущий список.
2. `POST …/select` — `selected=true` у выбранных; `manual_urls`, если дали ссылку.
3. `POST …/download` — для каждого акта URL в порядке: ваша ссылка → curated `known_sources` (известные официальные URL по названию) → SearXNG строго по allowlist.
4. HTML/PDF → `knowledge_raw/` → очищенный текст в `knowledge_text/` → нарезка на чанки (в т.ч. по статьям) → embeddings → `knowledge_index.json`.
5. Опционально sync `.txt` в коллекцию Knowledge Open WebUI.

Уже скачанный файл повторно не трогается.

## 6. История 3. Акт не скачался

**Как аудитор.** В ответе «скачано 4, не скачалось: 1» и название акта. SearXNG часто ловит 403 с поисковиков — это ожидаемо, не «агент сломался».

### Что написать

Повторить уже утверждённые (лежащее не перезапишет):

```
скачай
```

или `скачай ещё раз`.

Подложить URL на провалившийся пункт:

```
к 7 url https://nbrb.by/legislation/documents/полный-путь
```

Посмотреть состав библиотеки:

```
документы
```

Синонимы: `библиотека`, `файлы`, `архив`, `покажи акты`.

### Что вы увидите

Список: название — «скачан» / «не скачался», плюс ссылка на zip.

Проверьте zip глазами: там должны быть **утверждённые** вами акты, а не «то, что модель вспомнила».

### Под капотом

`документы` → `GET …/library`. Повтор `скачай` без новых номеров берёт уже `selected` id и снова гоняет download. LLM не участвует.

Если URL с `...` или `…` — агент ответит, что ссылка обрезана, и не качнёт.

## 7. История 4. Саммари в Word

**Как аудитор.** Библиотека скачана. Читать ГК целиком не хотите: нужен обзор на 6–10 страниц со ссылками на статьи.

### Что написать

```
саммари
```

Синонимы: `сводка`, `бриф`, `docx`, `word`, `обзор актов`, `файл word`.

Пересобрать после докачки актов:

```
саммари заново
```

Повтор без `заново` отдаст уже готовый файл, если состав библиотеки не менялся.

Не путать с вопросом про статью: «статья 625 ГК?» — это вопрос к базе, не сборка Word.

### Что вы увидите

Статусы несколько минут: «Готовлю обзор…», затем по актам «Саммари акта 3 из 10: …», «Пишу обзор проверки…».

В чат **полный Word не копируется**. Придёт ссылка на `.docx` и короткий дайджест (первые строки карточек).

В файле:

- обзор нормативного контура проверки;
- карточка по каждому скачанному акту (зачем нужен, ключевые нормы, что смотреть, пробелы);
- приложение: фрагменты `[n]` со статьёй/пунктом и официальным URL.

Номера `[n]` в тексте — **не** статьи закона, а ссылки на фрагменты в конце файла. Статья указана рядом с фрагментом.

Это черновик для чтения глазами, не мнение аудитора.

### Под капотом

`GET …/knowledge/brief/stream` (при `заново` — `?force=true`).

Для каждого скачанного акта:

1. Отбор релевантных чанков по keywords проверки (не весь кодекс).
2. **Вызов LLM** с ролью «старший аудитор»: только эти фрагменты, ~страница A4, после тезиса номер `[n]`, не подменять право РБ нормами РФ/IFRS.
3. Затем ещё один вызов: синтез обзора по карточкам.

Word и Markdown пишутся в `summaries/`. Чат получает ссылку и дайджест.

**Что получает LLM на карточке акта.** Тема проверки, keywords, название документа, блок фрагментов вида `[3] статья 625 / источник URL / текст`. Просят разделы: зачем акт, ключевые нормы, что проверять, риски, чего нет во фрагментах.

**Что отвечает LLM.** Связный русский текст с `[n]`. Если фрагментов мало — должна честно написать о пробеле, а не додумать главу кодекса. Pipe этот текст в чат не дублирует.

## 8. История 5. Спросить норму

**Как аудитор.** Word прочитан, в программу проверки нужна конкретная норма: валютная оговорка в договоре с резидентом.

### Что сделать в UI

Пишите **в том же чате**, где создали проверку. Новый чат = пустая библиотека.

### Что написать

Хорошие вопросы — про норму из **этой** библиотеки, один вопрос за сообщение, лучше с `?` или с «какой / что / где / можно ли»:

```
Можно ли в договоре аренды с резидентом РБ устанавливать арендную плату в евро?
```

```
Какой срок возврата валютной выручки по аренде нерезиденту?
```

```
Какая статья НК регулирует НДС при сдаче в аренду нежилого помещения?
```

```
Где в ГК сказано про государственную регистрацию договора аренды недвижимости?
```

Как помочь поиску: назовите предмет («аренда нежилого», «валютная оговорка»); если знаете акт — скажите («в инструкции 38», «по НК»).

Плохо: `Расскажи всё про аренду` (слишком широко).  
Плохо: `Сравни с Россией и IFRS` (в библиотеке этого нет).  
Плохо: `Сколько начислено аренды по договору №17?` (это **факт** из клиентских данных; контура фактов ещё нет).

### Что вы увидите

Статус: «Ищу ответ в приложенных документах…»

Потом текст ответа и блок:

```
**Откуда в базе знаний:**
- Гражданский кодекс …: дословный обрезок фрагмента…
```

Если фрагментов нет — в блоке будет отказ вроде «в приложенных документах этого не нашлось». **Не считайте ответ нормой**, если цитат нет. Переформулируйте с названием акта или утвердите недостающий документ и `скачай`.

### Под капотом

`POST …/knowledge/ask` с вашим вопросом как есть.

1. Вопрос эмбеддится `qwen3-embedding` (та же модель, что строила индекс).
2. Чанки ранжируются: пересечение слов + cosine. Берётся top-k (по умолчанию 8).
3. Эти куски кладутся в промпт. **Веб-поиска на этом шаге нет.**

**Что получает LLM.** Системная роль: ассистент внутреннего аудитора РБ; опираться в первую очередь на фрагменты; цитировать документ и статью; нет ответа во фрагментах — так и сказать; не выдумывать номера норм. Пользовательский блок: тема проверки, keywords, ваш вопрос, пронумерованные куски `[1] Название акта + текст`.

**Что отвечает LLM.** Короткий ответ по-русски. Pipe **дописывает** блок «Откуда в базе знаний» из тех же чанков (обрезки до ~220 символов) — даже если модель ответила гладко. Источник истины для вас — блок цитат и файл в zip, не красноречие абзаца.

Модель видит только top-k. Если нужная статья не попала в выборку — её «нет», хотя файл лежит в кейсе. Тогда сузьте вопрос или укажите акт.

## 9. История 6. Новая проверка

**Как аудитор.** Аренду закрыли, дальше касса.

Не пишите «Проверка кассовых…» в старом чате: Pipe может создать **новый** кейс в той же ленте и вы запутаете библиотеки.

1. Слева **Новый чат**.
2. Снова модель **Аудитор** (проверьте шапку).
3. Опишите новую проверку шаблоном из истории 1.

Список прошлых проверок на сервере (если в этом окне кейса ещё нет): `кейсы` или `проверки`. Вопросы задавайте в чате той проверки, где уже скачаны документы.

## 10. Шпаргалка фраз

| Написать | Зачем | LLM вызывается? |
|---|---|---|
| `Проверка …, слово, слово` | Создать кейс и получить список актов | да, propose |
| `утверждаю 1, 2, 4` | Выбрать и скачать | нет |
| `утверждаю все обязательные` | Только priority=1 | нет |
| `к 3 url https://…` | Подложить официальную ссылку | нет |
| `скачай` | Повторить download выбранных | нет |
| `документы` | Состав библиотеки и zip | нет |
| `саммари` | Word-обзор | да, карточки + синтез |
| `саммари заново` | Пересобрать Word | да |
| вопрос с `?` / «какой / можно ли» | Норма из индекса кейса | да, ask |
| `статус` | Сколько предложено / выбрано / скачано | нет |
| `кейсы` / `проверки` | Список кейсов на сервере | нет |
| `помощь` / `help` / `?` | Шпаргалка в чате | нет |

Как Pipe выбирает фазу (первое совпадение побеждает):

1. пусто / `помощь` → шпаргалка;
2. `саммари` / `сводка` / `бриф` / `docx` → Word;
3. `утверждаю` / `скачай` / `к 3 url …` → select + download;
4. `документы` / `библиотека` → список файлов;
5. `статус` / `кейсы` → состояние;
6. текст похож на новую проверку **и не вопрос** → create + propose;
7. в чате есть кейс и текст похож на вопрос → ask;
8. иначе, если кейс есть → всё равно ask;
9. иначе → шпаргалка.

Поэтому «Проверка аренды…» в чате с уже живым кейсом может начать новый кейс, если фраза не выглядит как вопрос. Для вопросов ставьте `?`.

## 11. Что видит LLM на каждом шаге

Кратко: модель **не видит** ваш диалог Open WebUI как историю чата GPT. Каждый вызов — отдельный промпт, собранный сервером.

### Предложить акты (`propose`)

- Роль: методолог, только НПА РБ, без блогов.
- Вход: название проверки + keywords.
- Выход: JSON. В чат попадает уже отформатированный список.
- Температура низкая (0.2), формат ответа принудительно JSON.

### Ответ по норме (`ask`)

- Роль: ассистент аудитора; фрагменты важнее «памяти» модели.
- Вход: вопрос + top-k чанков из **утверждённой и скачанной** библиотеки.
- Выход: текст. Цитаты в чат дописывает Pipe из тех же чанков.
- Если чанков нет (ещё не скачали) — ошибка «база знаний пуста», модель не вызывается.

### Карточка акта и обзор (`саммари`)

- Роль: старший аудитор; только фрагменты; `[n]` после тезиса; не РФ/ЕС/IFRS.
- Вход на акт: keywords проверки + 10 фрагментов этого файла.
- Вход на обзор: все карточки + каталог `[n] — акт — статья — URL`.
- Выход: длинный текст в Word, в чат — ссылка и дайджест.

### Когда модель молчит

Утверждение, скачивание, `документы`, `статус`, `помощь` — чистый код. «Галлюцинация статьи» на этих шагах невозможна: текста модели нет.

## 12. Карта под капотом

```
Вы (браузер :3000)
    │  обычные сообщения
    ▼
Pipe «Аудитор»          Python, Admin → Функции, файл audit_agent.py
    │  фаза КОДом, HITL: download только после «утверждаю»
    ▼
Audit Tool Server       FastAPI :8100
    ├─ Ollama           qwen3.6:35b — propose, карточки, ответы
    ├─ Ollama embed     qwen3-embedding — векторы
    ├─ SearXNG          URL только по allowlist РБ
    └─ диск             backend/data/audit_cases/{case_id}/
```

Почему Pipe, а не «просто Qwen в чате»: локальная 35B плохо держит native tool-calling и может вызвать download без вашего «утверждаю». Фазу выбирает код.

### Папка кейса

```
backend/data/audit_cases/{case_id}/
  case.json              система записи: статус, кто выбран, URL
  manifest.json          что скачали, sha256, источник URL
  knowledge_raw/         первоисточники (html/pdf)
  knowledge_text/        очищенный текст
  summaries/             карточки актов + sammari_*.docx + brief.md
  knowledge_index.json   чанки для вопросов
  library.zip            архив сырых файлов
```

### Норма ≠ факт

| | Норма (сейчас) | Факт (план) |
|---|---|---|
| Что | НПА, инструкции НБРБ | Выгрузки, договоры, обороты |
| Откуда ответ | RAG по библиотеке кейса (`/knowledge/ask`) | SQL / tools по файлам клиента |
| Нельзя | Сочинять статью | Класть Excel в ту же Knowledge |

В чате с агентом не прикрепляйте клиентские Excel «чтобы модель посмотрела».

Вопрос аудитора в продукте идёт через Pipe → `/knowledge/ask` сервера, а не через «прикрепить Knowledge к обычной модели». Коллекция Open WebUI — опциональный дубль `.txt`, если задан API-ключ в Valves.

## 13. Чего агент не делает

- не ставит вывод «нарушение / не нарушение»;
- не подписывает working paper;
- не ищет по всему интернету;
- не качает акт, пока вы не утвердили номер или не дали URL;
- не считает ответ нормой, если блока цитат нет;
- не ведёт две проверки в одном чате;
- не отвечает по суммам договора и выгрузкам клиента (этого контура ещё нет).

## 14. Если что-то пошло не так

| Симптом | Что сделать |
|---|---|
| В списке моделей нет «Аудитор» | Админ: Функции, ID `auditor`, переключатель **Включено**, F5. [`AGENT.md`](../seed/openwebui/AGENT.md) |
| Отвечает «голый» Qwen, без списка актов | В шапке чата выбрана не модель **Аудитор** |
| «В этом чате ещё нет проверки» | Опишите проверку заново **в этом** окне; не удаляйте ответы агента с меткой кейса |
| «Не поняла, какие документы взять» | `утверждаю 1, 2` — номера как в последнем списке |
| «Ссылка обрезана» | URL из адресной строки, без `...` |
| Акт не скачался | `скачай` или `к N url https://…` |
| «Сервер проверки не отвечает» | Compose: контейнер `audit-tools` жив; Valves Pipe: `AUDIT_API=http://backend:8100` |
| Саммари долго / таймаут | Подождите; в Valves `BRIEF_TIMEOUT_SEC`; повтор `саммари` |
| Ответ без цитат / «этого нет» | Акта нет в библиотеке или вопрос слишком общий. Утвердите акт или сузьте вопрос |
| Модель выдумала РФ / IFRS | В библиотеке этого нет; не принимайте. Спросите с указанием акта РБ |
| Выбрали обычный Qwen | Чат без HITL. Переключите модель на **Аудитор** |

Разработчикам: как устроен retrieval — [`RAG_для_разработчика.md`](RAG_для_разработчика.md). Фазы Pipe одной таблицей — [`AUDITOR.md`](AUDITOR.md).
