## Правило отбора работ

Прежде чем писать что-то своё, три вопроса:

1. Это уже есть в Open WebUI / Ollama / SearXNG / DuckDB / Word-шаблоне?
2. Если нет — хватит ли tool-скрипта на 50–150 строк, который дергает наше API?
3. Если нет — это домен проверки (кейс, HITL, НПА РБ, trail)? Тогда пишем в Audit Tool Server.

Нет → не делаем. Особенно: экраны, админки, второй RAG, второй агент.

## v0.0.1 — что уже есть (демо)

Аудиторский поток живёт в чате Open WebUI, модель **Аудитор** (Pipe). Один вход: http://localhost:3000.

```
описать проверку
  → список НПА (модель предлагает)
  → утверждаю 1, 2, 4          ← HITL, без этого ничего не качается
  → скачивание + индекс
  → саммари / саммари total / программа проверки   (Word; программу — таблица вопросов, можно `программа проверки 8`)
  → гипотезы                   → Excel
  → утверждаю гипотезы 1, 3, 5 ← HITL; свои — `плюс …` или .xlsx
  → аудиторское мнение         → Word, раздел I
  → аудиторское заключение     → Word, полный черновик
  → вопрос …                   → цитата из базы
  → без префикса               → обычный чат
```

**В коде**

- FastAPI: кейс (`created → proposed → selected → downloading → ready / failed`), propose / select / download, extra_titles, manual URL, known_sources, SearXNG по allowlist, extract, индекс, ask, sync Open WebUI, обычный чат.
- Word: обзор актов (`саммари`), конспект из знаний модели (`саммари total`), программа проверки (таблица «вопросы, подлежащие аудиту»), раздел I (`аудиторское мнение`), полное заключение (`аудиторское заключение`). Excel: чеклист гипотез. Стримы SSE, повтор `… заново`. Шрифт мнения/заключения: `-c` Calibri, `-t` Times New Roman. Свои гипотезы: `плюс …` в чате или .xlsx.
- Pipe: фазы **кодом**, не свободный ReAct. Download только после «утверждаю». Гипотезы в мнение — только после `утверждаю гипотезы …`. Вопрос к базе — только с префиксом `вопрос …`. Иначе `POST /api/v1/chat`. Подсказки следующих шагов — фразы в ответе, не отдельный UI. Засев Pipe при `compose up`, если в `.env` есть `OPENWEBUI_API_KEY` (`pipe-seed`).
- `GET /cases`, в чате `кейсы` / `статус`. Файловый store, без БД.
- `docker-compose.yml`: SearXNG + Open WebUI + backend; frontend только `--profile lab`.
- Промпты в `docs/prompts/`. Сводка для правки: [PROMPTS.md](PROMPTS.md), рабочий Word: [Промпты агента.docx](Промпты агента.docx).
- Тесты backend: extra_titles, extra_hypotheses, download URLs, brief, hypotheses, opinion, conclusion, case_context, Pipe classify.

**Ещё нет**

- Данных клиента, тестов проверки, WP, rules.
- «Открой кейс X» в новом чате.
- Корневой `.env.example` и one-pager установки без репозитория (остаток v0.2). Без `OPENWEBUI_API_KEY` Pipe всё ещё вставляют руками ([AGENT.md](../seed/openwebui/AGENT.md)).

Гипотеза «фронт не нужен для HITL» **подтверждена**. `frontend/` заморожен.

Инвариант 0.0.1: мнение и заключение — **черновики** после HITL по гипотезам, не акт СВА и не подпись.

## v0.1 — Цитата, которой можно доверять

Цель: показать СВА ответ с цитатой и не краснеть. Это ядро доверия, как «модель видит *этот* файл» у Cursor.

- [x] Перед sync: нормализация `.txt` → markdown с `## Статья N` / `## Пункт N`, заголовок акта, URL, дата.
- [x] Eval: 20–30 золотых вопросов по 3–4 типовым актам (есть в тексте / нет в тексте / поиск по номеру статьи / перефраз). Гонять после смены embedding и chunk. Четыре золотых теста из [RAG_для_разработчика.md](RAG_для_разработчика.md) — минимум.
- [x] Trail: в `case.json` или `trail/*.jsonl` — какие file_id ушли в Open WebUI, какой чанк в ask.
- [ ] Обогащение промптов по [Промпты агента.docx](Промпты агента.docx) → обратно в `docs/prompts/*.txt` (методология, не новый код).

Не делать в 0.1: вторую vector DB, тесты проверки, WP, DuckDB, React.

Выход: на вопросе, которого нет в библиотеке, модель отказывается; на вопросе, который есть — цитата из нужной статьи.

## v0.2 — Коробка без Admin

Цель: `compose up` → открыл URL → чат с уже вставленным Pipe. Человек без репозитория ставит стенд.

- [x] Засев Pipe при `compose up` при `OPENWEBUI_API_KEY` (`pipe-seed`). Без ключа — ручная вставка в Admin.
- [ ] `.env.example` на **корне** compose (порты, модели) — дубль для человека без захода в `backend/`.
- [ ] Документ «поставил → работает» на одну страницу (образы, pull моделей, офлайн-бандл для банка).
- [ ] Скрипт: проверка GPU/RAM, pull моделей, healthcheck контейнеров, сообщение «откройте http://…».

Не делать в 0.2: новый фронт, Postgres, инсталлятор Windows как продукт сам по себе без засева Pipe.

Выход: можно давать человеку без доступа к репо и без инструкции «вставьте функцию в Admin».

## v0.3 — Несколько проверок без путаницы

Цель: 2–3 проверки на одной машине, не потерять библиотеку.

- [ ] «Открой кейс X» в чате (привязать уже скачанную библиотеку к новому окну).

## v0.4 — Факт: данные клиента без RAG по Excel

Цель: вопрос «сколько» идёт через код. Норма и факт — разные механизмы.

- [ ] Каталог `evidence/` в кейсе. Загрузка: Files Open WebUI **в кейс через tool** или drop в папку. Не в коллекцию `npa-*`.
- [ ] Tool `evidence_sql`: DuckDB `read_xlsx` / csv, лимит строк в ответе, в trail — запрос и имя файла.
- [ ] Запрет: этот tool не вызывает SearXNG и не пишет в Knowledge НПА.
- [ ] 2–3 типовых запроса-примера в system prompt (сумма, период, группировка).

`POST /api/v1/cases/{id}/knowledge/upload` — загрузка **актов**, не evidence. Не использовать его для Excel клиента.

Выход: «сколько начислено» не путается со «статьёй 625».

## v0.5 — Тесты и WP, не генератор отчёта

Цель: ускорить бумагу, не подписать её за аудитора. Программа Word уже есть в 0.0.1 — не дублировать её SPA.

- [ ] Модель данных теста: цель, критерий, источник нормы (id акта + статья), выборка, шаги, ожидаемый ok / finding.
- [ ] Tool `propose_tests` → HITL `select_tests` (как с НПА и гипотезами).
- [ ] Шаблон WP банка в `seed/templates/*.docx` (норма / факт / вывод / ссылка на файл). Заполнение через python-docx. Статус всегда `draft`.
- [ ] Фаза в чате: «предложи тесты» / «собери черновик WP по тесту N». Логика в сервере, не в Pipe.

Мнение и заключение **уже в 0.0.1**. Их не смешивать с WP: закрывающие черновики после гипотез ≠ рабочие бумаги по выборке.

Выход: аудитор копирует черновик WP в свой контур, а не в наш «портал».

## Порядок, если времени мало

Демо 0.0.1 уже показывает контур до заключения. Дальше ценность такая:

1. **v0.1** — цитаты и eval (доверие СВА).
2. **v0.2** — засев Pipe, «поставил → работает».
3. **v0.3** — «открой кейс X», если путают окна.
4. **v0.4** — DuckDB / evidence.
5. **v0.5** — тесты и WP.
6. **v0.6** — rules.
7. **v0.7** — пакет аренды.

## Критерии «мы близко к Cursor»

Не «есть GPT в чате», а:

- [x] Список НПА нельзя скачать без утверждения аудитора.
- [x] Excel клиента не всплывает в ответе про закон (контура фактов нет; `вопрос` идёт только в индекс НПА).
- [x] Нет второго окна «настоящего UI», без которого нельзя работать.
- [x] Цепочка до черновика заключения жива: гипотезы → HITL → мнение → заключение.
- [ ] Человек без этого репо поднимает систему одной командой (включая Pipe) и задаёт `вопрос …` по акту с цитатой.
- [x] На вопросе, которого нет в библиотеке, модель отказывается, а не сочиняет статью. Eval: `backend/eval_rag.py` и `tests/test_ask.py`.
- [ ] Повторная проверка той же темы начинается с пакета, а не с пустого промпта.

Идеи сверх каркаса — в [IDEAS.md](IDEAS.md), в спринт попадают только если не спорят с этим планом.
