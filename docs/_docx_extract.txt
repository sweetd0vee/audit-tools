Вариант сборки: Open WebUI + Pipelines + Ollama + SearXNG + Chroma/pgvector + Audit Tool Server + Continue.dev/AiderВерсия 1.0  |  20.08.2026  |  Конфиденциальные данные — только on-prem
0. Цель и ожидаемый результат
Вы строите локальный аналог Cursor для внутреннего аудита банка. Вход: название проверки + произвольные данные (Excel/CSV/SQL). Выход: план проверки, гипотезы, тесты, исключения, рабочие документы (WP), draft findings со ссылками на нормативку РБ — без отправки данных в интернет.
Что должно получиться через 8 недель:
Чат в Open WebUI, где аудитор пишет: «Проверка X + файл Y»
Агент сам проходит фазы: scope → data quality → tests → report
Числа и нормы — только из tools и локального RAG (не «из головы» модели)
Excel WP и findings на диске в /audit_cases/{case_id}/
Полный audit trail: какие tools вызывались и с какими аргументами
Главный принцип качества:
LLM планирует и объясняет. Tools доказывают (pandas, SQL, compliance rules, Excel). QA-валидатор блокирует findings без evidence и без ссылки на норму.

3. День 1 — поднять базовый стек
Цель дня: чат с локальной 72B-моделью в Open WebUI + веб-поиск через SearXNG. Пока без ваших audit-tools.
3.1 Установить Ollama и скачать модели
Скачайте Ollama с https://ollama.com и установите. Затем в PowerShell:
ollama pull qwen2.5:72b-instructollama pull qwen2.5:32b-instructollama pull bge-m3ollama list
Если 72B не влезает в VRAM — начните с qwen2.5:32b-instruct, но для качества гипотез и планов проверки лучше 70B+.
Проверка:
ollama run qwen2.5:72b-instruct "Ответь одним словом: работает?"
3.2 Поднять Open WebUI
docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway `  -v open-webui:/app/backend/data `  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 `  -e WEBUI_SECRET_KEY=change-me-to-long-random-string `  --name open-webui `  ghcr.io/open-webui/open-webui:main
Откройте http://localhost:3000 → создайте первого пользователя (admin).
Важно для конфиденциальности: не добавляйте OPENAI_API_KEY и другие облачные ключи. Модель должна идти только через Ollama.
3.3 Поднять SearXNG

6. Неделя 2 — Pipelines (agent loop)
Цель: воспроизвести поведение Cursor — план → действие → результат → следующий шаг → retry при ошибке.
6.1 Установка Pipelines
mkdir pipelinesdocker run -d -p 9099:9099 `  -v ${PWD}/pipelines:/app/pipelines `  --name pipelines `  ghcr.io/open-webui/pipelines:main
В Open WebUI: Admin → Settings → Pipelines → URL http://host.docker.internal:9099 → Connect.
6.2 Первый pipeline: 4 фазы (упрощённо)
Пока не все 10 фаз — начните с минимального цикла:
INTAKE — разобрать название проверки + пути к файлам
DATA_QUALITY — вызвать data_profile + data_quality
HYPOTHESES — LLM генерирует ≥10 гипотез по profile JSON
REPORT — черновик отчёта + ссылки на trail
Правило retry: если tool вернул ошибку — передать traceback модели, повторить шаг до 3 раз, затем остановиться с понятным сообщением аудитору.
6.3 Системный промпт агента (вставить в модель)
Ты — агент внутреннего аудита банка (Республика Беларусь).Работай фазами: INTAKE → DATA_QUALITY → HYPOTHESES → REPORT.Запрещено выдумывать числа и пункты законов.Числа — только из tools. Нормы — только из #Knowledge или web allowlist.Каждый вывод должен иметь evidence (файл/строка) или norm_reference.Если данных недостаточно — явно запроси дополнительные файлы.Пиши на русском. Формат ответа: Scope / Data / Hypotheses / Findings / Next steps.

9. Конфиденциальность: жёсткие правила
Обязательно:
Ollama и Open WebUI без облачных API-ключей
Клиентские данные только в /audit_cases/{case_id}/ — не в общий Knowledge
Web search: allowlist доменов; в query не подставлять счета/ФИО/суммы
Docker: data-контейнеры без исходящего интернета (кроме SearXNG с фильтрами)
SQL (если добавите) — только read-only replica
RBAC: auditor / reviewer / admin
Audit trail append-only
Запрещено:
OpenAI / Claude / Gemini / облачные embeddings
Tavily / облачный Firecrawl с передачей текста проверки
Отправка фрагментов Excel в веб-поиск

Сообщение аудитора:
Проверка: Соблюдение лимитов на операции с аффилированными лицами.Период: 2025Q1.Данные: /audit_cases/2025Q1_affil/ops.xlsx и counterparties.xlsx.Выполни полный цикл: scope → качество данных → гипотезы → тесты → исключения → рабочие документы.
Ожидаемый ответ агента (структура):
A) Scope & Norms — список актов и пунктов (из RAG/web)
B) Data Summary — строки, качество, mapping колонок
C) Hypotheses & Tests — таблица H0/H1/метод/результат
D) Exceptions — id, сумма, ссылка на строку, severity
E) Conclusion — draft finding или «существенных нарушений не выявлено»
F) Evidence Index — пути к файлам, trail
G) Next Steps — что уточнить у бизнес-подразделения
