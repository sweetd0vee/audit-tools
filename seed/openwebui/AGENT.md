# Первый агент (v0.0.1)

Агент — не «ещё одна модель». Это **цикл с руками и стоп-краном**. Версия Pipe — `0.0.1` (шапка `audit_agent.py`). Это демо-базовая линия; что добавлять: [`docs/PLAN.md`](../../docs/PLAN.md).

```
сообщение аудитора
  → понять фазу (код, не свободный ReAct)
  → вызвать API кейса (руки)
  → если нужен человек — остановиться
  → иначе следующий tool
  → ответ + цитата
```

Локальный Qwen 27B плохо держит native tool-calling. Поэтому **главный агент — Pipe**: фаза и HITL в Python. Модель предлагает список НПА и отвечает по фрагментам, но не решает «качать или нет».

```
Аудитор  →  Pipe «Аудитор»  →  Audit Tool Server  →  Ollama / SearXNG / диск
                 ↑ HITL: download только после «утверждаю»
```

Не пишем LangGraph, мультиагентов и свой чат.

## Что поставить (5 минут)

Русский интерфейс Open WebUI. Если пункт называется иначе — ищите то же место по смыслу: функции, создать, включить.

**Предпочтительно:** `docker compose up -d --build` и ключ `OPENWEBUI_API_KEY` в корневом `.env`. Сервис `pipe-seed` склеит `intent.py` + `audit_agent.py` и засеет Pipe `auditor` через API. В чате должна появиться модель **Аудитор** (иконка не `ol`).

Если ключа ещё нет (первый вход, админ только что создан):

1. Open WebUI → Настройки → Аккаунт → API Keys — создайте ключ, положите в `.env`.
2. `docker compose up -d pipe-seed` (или вставьте paste вручную ниже).

Вручную, без API:

1. Откройте http://localhost:3000
2. Функции **нет** в Рабочем пространстве (там только Модели, Знания, Промпты, Скиллы, Инструменты). Pipe живёт у админа.
3. Внизу слева нажмите на имя (**Arina**) → **Панель администратора**.  
   Или сразу откройте http://localhost:3000/admin/functions
4. Слева в админке пункт **Функции**. Справа **Создать**.
   - **ID Функции:** `auditor` (только латиница, не «Аудитор»)
   - **Название Функции:** `Аудитор`
5. Вставьте **склеенный** текст: `python seed/openwebui/seed_pipe.py --print` (не сырой `audit_agent.py` — ему нужен `intent.py`).
6. **Сохранить**.
7. В списке функций переключатель должен стать **Включено**. Выключенная функция в чате не видна.
8. Шестерёнка / **Параметры:** `AUDIT_API=http://backend:8100` → **Сохранить**.
9. Обновите страницу чата (F5). **Новый чат** → **Выберите модель**.
   Ищите **Аудитор** — иконка **не** `ol` (это не Ollama). В поиске моделей наберите `Аудитор`.
   `qwen3.8:27b` и остальные `ol` — обычные модели, агент это не они.

Напишите:

```
Проверка аренды коммерческой недвижимости, аренда, валюта, НДС
```

Потом: `утверждаю 1, 2, 4`. Нет в списке: `плюс Инструкция НБРБ № 38`. Вопрос к базе: `вопрос …`. Дальше — гайд [`docs/GUIDE.md`](../../docs/GUIDE.md), шпаргалка [`docs/AUDITOR.md`](../../docs/AUDITOR.md).

Полный чеклист качества (embedding, chunk, `num_ctx`, что выключить): [`docs/OPENWEBUI.md`](../../docs/OPENWEBUI.md).

## Что поставить (если меню на английском)

1. `docker compose up -d --build` — Open WebUI :3000, backend :8100.
2. Open WebUI → **Admin Panel → Functions → Create** (не Workspace).
3. Вставьте склеенный paste (`python seed/openwebui/seed_pipe.py --print`) или дождитесь `pipe-seed`.
4. Включите функцию (toggle). Valves: `AUDIT_API=http://backend:8100`  
   Если WebUI не в Docker — `http://localhost:8100`.
5. Новый чат → в списке моделей **Аудитор**.

Не путать с Workspace → Models → «Аудитор» на базе Ollama. Pipe сам появляется как модель.

Полный сценарий аудитора (навигация, фразы, саммари, вопросы, под капотом): [`docs/GUIDE.md`](../../docs/GUIDE.md). Шпаргалка фаз: [`docs/AUDITOR.md`](../../docs/AUDITOR.md).

Кратко: описать проверку → **ждать утверждения** → `утверждаю 1, 2, 4` (нет в списке: `плюс Название акта`) → `саммари` / `саммари total` / `программа проверки` → `гипотезы` (Excel) → к базе только `вопрос …`. Без префикса — обычный чат, не цитата. «Все обязательные» = только `priority=1`. Ссылка: `к 3 url https://pravo.by/...` (полный URL, без `...`).

## Запасной путь: Tools + Ollama

[`tools/audit_case.py`](tools/audit_case.py) — руки без цикла. Workspace → Tools → вставить → привязать к чат-модели → Function calling **Native**.

## Почему это уже агент, а не скрипт

| Часть | Где |
|---|---|
| Память проверки | `case_id` в чате (`<!--audit-case:...-->`) + файлы сервера |
| Руки | HTTP на уже существующие эндпоинты |
| Мозг | Ollama: propose, ask, саммари, total, программа, гипотезы, обычный чат на сервере; Pipe не дублирует RAG |
| Стоп-кран | нет select — сервер не качает; Pipe не идёт дальше списка |
| Наблюдаемость | статусы в UI («Создаю кейс…», «Качаю…») |

Круче станет не от второго агента, а когда цитата стабильна и 27B не нужна для выбора фазы. Следующий шаг после этого файла — золотые вопросы RAG, не «оркестратор».
